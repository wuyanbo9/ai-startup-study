**它凭什么长这么快 ——** 因为它卖的计量单位，恰好是「agent 干活」这件事的最小颗粒。一个编码 agent 每试一次改动、一个 RL 训练任务每跑一个 episode，都需要一台能跑任意不可信代码、用完就扔的机器；用时几秒到几分钟，数量却是几十万级。这件事在人类工程师的时代不存在 —— 人一天开一次开发环境，所以云厂商把虚拟机的开机时间优化到 30 秒就收手了。Daytona 把这个数字做到 27 毫秒，并且让这台机器能**暂停保态、分叉成并行副本**（CEO 的说法是「你可以把这台电脑原地复制成两台，两个结果都试一遍」）。于是它的收入曲线不跟着模型能力走，跟着**「agent 每天尝试多少次」**走。CEO 把这条分工讲得最清楚：「**推理云是 agent 思考的地方，我们的云是 agent 干活的地方**」。更关键的是时间点：它 2025 年 4 月就上线了，但连续 50.9% 月增是从 **2026 年 1 月**才开始的 —— 2025 下半年它基本走平（见第 2 节的曲线重建）。真正的拐点不是产品上线，是 RL 训练环境和后台编码 agent 同时进入生产的那个季度。

## 1. 核心产品

**卖什么**：一个叫 sandbox 的东西 —— 本质是一台通过 API 创建的、隔离的、有状态的虚拟机。官方把整个产品线叫 **Agent Execution Cloud**（agent 执行云），定义成「给 agent 的电脑、浏览器和存储」这一层。

**用户在什么场景下调用它**：没有人「打开」Daytona。调用方是程序。三类典型负载 `[官方]`：

1. **代码执行** —— 一个编码 agent 生成了一段代码，要跑一遍看报不报错。这段代码不可信，不能碰生产环境。
2. **computer use** —— agent 需要一个带浏览器和桌面的完整操作系统去点按钮、填表单。
3. **强化学习 / 评测环境** —— 训练或评测一个 agent，要在隔离环境里成千上万次重放同一个任务。这是 2026 年增量最猛的一类，也解释了为什么 Snorkel、Surge AI、Turing、AfterQuery 这批「训练数据与环境供应商」同时出现在客户名单里（本档已分析过其中三家）。

**Before / After**：

| | Before | After |
|---|---|---|
| 怎么拿到一台机器 | 自己在 Kubernetes / GKE 上搭沙箱池，或直接开 EC2 | 一次 API 调用（Python / TypeScript / Go / Ruby / Java SDK） |
| 就绪时间 | 云虚拟机 30 秒到数分钟 `[官方口径]` | **27ms 启动、<90ms 端到端** `[官方]` |
| 为了削掉这段延迟要付什么 | 养一个常驻的热机池：机器闲着也烧钱 | 按秒计费，用完销毁；池子是 Daytona 的问题 |
| 状态 | 容器/函数跑完即忘，中间状态要自己外存 | **暂停保态、恢复、快照、分叉成并行副本** |
| 覆盖面 | 自建一般只做 Linux 容器 | Linux / Windows / macOS / GPU 在同一个平台 |
| 规模撞墙的样子 | Writer 自建撑到每天 2 万沙箱后维护不下去 `[官方]` | 同一家在 Daytona 上单月开 30 万个 |

**替代的是什么**：替代**自建基础设施（软件 + 机器）**，完全不替代人。它不减少任何一个编制 —— 它减少的是平台工程师维护沙箱池的时间，和为了削峰而常驻的那堆闲置机器。这一点决定了它抢的是**云预算 / 基础设施预算**，不是人力预算，天花板因此比本档那些「替掉一个编制」的应用层公司低一个数量级（这个判断在第 2 节会被一个反向因素部分抵消：它的客单量跟着 agent 调用次数涨，而那个分母正在失控地变大）。

**一条必须记下的产品史**：Daytona 的开源仓库 `daytonaio/daytona` 攒到 **71.5k star、5.6k fork、2,744 次提交**，是开源项目里的头部量级；但它在 **2026 年 6 月被归档为只读，核心开发转入私有代码库** `[官方（GitHub 仓库页）]`。开源是它 2025 年拿到分发和投资人注意力的主要手段（A 轮报道明确说「开源发布帮它吸引了投资人兴趣」），拿到之后就收了。这对第 2 节的切换成本评估是个要紧的负面证据。

## 2. 商业模式

- **收费对象**：AI 公司的基础设施预算。决策人是平台工程或基础设施负责人，不过采购 —— 最初的增长几乎全是自助注册（官方称增长是产品驱动而非销售驱动，B 轮之前基本没有销售）。
- **定价结构**：**纯用量制、按秒计费、无席位、无平台费** `[官方，2026-10 定价页]`

| 资源 | 单价 |
|---|---|
| vCPU | **$0.0504 / vCPU-小时** |
| 内存 | **$0.0162 / GiB-小时** |
| 存储 | $0.000108 / GiB-小时（前 5 GiB 免费） |
| Windows OS | $0.0858 / vCPU-小时 |
| GPU（抢占式，$/小时） | B300 $4.08、B200 $3.59、MI355X $3.44、H200 $2.61、H100 $2.27、RTX PRO 6000 $1.74、RTX 5090 $0.74、RTX 4090 $0.57 |
| 免费额度 | $200 免费算力、注册不要信用卡；创业计划最高 $50k credits |
| 企业版 | 更高并发上限 + SSO + 审计日志 + BYOC（自带云），价格面谈 |

**这张价目表里藏着本篇最硬的一个事实。** 去抓第二名 E2B 的定价页：**$0.000014 / vCPU-秒 = $0.0504 / vCPU-小时，$0.0000045 / GiB-秒 = $0.0162 / GiB-小时** `[官方（E2B 定价页）]`。**两家公司的单价一分不差、小数点后四位完全相同。** 这不是巧合能解释的数字，这是一个已经完成价格发现的商品市场。Daytona 在这张表上唯一的差异化是**不收平台费**（E2B 要 $150/月 Pro、企业版 $3,000/月起底）、以及**覆盖面更宽**（E2B 是 CPU-only、单沙箱上限 8 vCPU / 8 GiB，没有 GPU、没有 Windows/macOS）。

- **单位经济**：毛利率**未公开**。能算的是和上游的价差 —— AWS `c7i.large`（2 vCPU / 4 GiB）目录价约 **$0.0892/小时** `[估算（第三方价格聚合站，2026-07 更新）]`，Daytona 同规格为 $0.0504×2 + $0.0162×4 = **$0.1656/小时**，**贵 1.86 倍**。表面看这是在超大规模云上加价转售；真实情况是它跑的是**自有 + 租用混合的裸金属机队**（CEO 称可在 1 万到 5 万并发 CPU 之间近乎瞬时伸缩），裸金属的单位成本远低于 AWS 目录价，所以毛利率大概率不难看。本档 Blacksmith 公布过同类生意的利用率—毛利曲线（利用率 10% → 毛利 35%，20% → 70%，35% → 85%+），可以当作量级参照 `[估算]`。

  **但这 1.86 倍的加价同时划出了它的客户边界，而且是可以算出来的：** 自建机器池的盈亏平衡利用率 = 0.0892 ÷ 0.1656 ≈ **54%**。也就是说，**谁能把自己的沙箱池利用率跑到 54% 以上，自建就更便宜。**负载越稳、规模越大的客户，越能跨过这条线。Writer 是个反例（它自建到每天 2 万沙箱反而迁了进来），因为它的负载是尖的 —— 单月 30 万个沙箱根本不是一个池子能摊平的。所以这条线的真实含义是：**它的护城河只对「负载是尖的」客户成立；负载一旦变平，客户就有了精确的离开理由。**

- **它从谁的预算里抢钱**：**云预算**，不是人力预算。但有一个抵消项值得点破 —— 它的收入分母不是客户数、也不是席位数，是**「agent 每天尝试多少次」**。这个分母的增速不由 Daytona 的销售能力决定，由上游模型能力和 agent 产品的渗透速度决定。好处是它坐在一条自己不用推的曲线上；坏处是它对这条曲线**没有任何控制权**。

**ARR 估算的推演（公司只给倍数，不给绝对值，所以必须自己夹逼）**

> **路径一（自上而下，按估值倍数）**：$1B 估值。2026 年 agent 基建类公司的常见口径是 20–30x 收入 run-rate（同期 Modal 的 $15.75B / $1B = 15.75x，是规模更大、增速更低的那一档，倍数理应更低）。$1B ÷ 30 ~ 20 得 **$33M–$50M**。
>
> **路径二（自下而上，按两个绝对点 + 25x）**：已知 2025-07 约 $3M。官方明确说 50.9% 的连续月增是**从 2026-01 起算**，这句话本身就是信息 —— 如果 2025 下半年也在高速增长，2026-01 的基线会高到让 25x 推出 $200M+，那么 $1B 估值只剩 5x，与 Dealroom「前 8% 的 B 轮估值」和同期 Modal 的 15.75x 都矛盾。所以合理假设是**2025 下半年曲线接近走平**（从 $3M 持平或小幅回落），取 2026-01 基线 $1.5M–$3M，×25 得 2026-09 为 **$37M–$75M**。
>
> **两条路径的交集是 $37M–$50M。**放宽到 **$35M–$80M、中枢 $50M** `[估算]`。按中枢算，$1B 估值 = 20x，与同档公司对得上。
>
> **口径警告（两条，都要记）：**①公司从不公布绝对 ARR，只公布倍数和「最快」。路径二的反推说明，**「25x」这个漂亮数字的前提是 2025 下半年有半年原地踏步** —— 一个只报倍数的公司，选的往往就是倍数最好看的那个起点。②「$3M ARR in 95 days」这个被引用最多的说法来自 CEO 的播客访谈；同期的官方博客和 A 轮稿用的是「forward revenue run rate（前瞻收入 run-rate）」而非 ARR，媒体版本则是「不到三个月 $1M、六周后翻倍（即 $2M）」。**同一段历史存在 $2M 和 $3M 两个口径**，本篇取官方书面口径作为主线、把 $3M 标为访谈口径。

**不可替代性（必答）**

| 问题 | 答案 |
|---|---|
| **自己造了什么** | 毫秒级有状态沙箱调度器：27ms 启动、暂停保态、可分叉复制、混合裸金属机队。真自研，但约 100 家在做同一件事。 |
| **转手卖什么** | 裸金属 CPU / GPU 机时。按 AWS 目录价折算，同规格售价是上游的 1.86 倍，即上游占售价约 54%。 |
| **抽掉 AI 还剩什么** | 一门按秒计费的 microVM 出租生意。它自己在 2025-02 验证过结论：卖不动，当时账上只剩三个月。 |
| **换掉它要付什么** | 几乎只有改 SDK 调用。AfterQuery 从自建 GKE 一天切完；与 E2B 单价完全相同；开源仓库已归档。 |
| **上游原生做了会怎样** | 模型厂不会自己卖机时，但 Modal 的沙箱线已 $300M、是它的 6 倍，K8s 自建才是头号对手。 |

**不可替代性：弱。**理由不在任何一条单独的证据上，在于三条证据指向同一个方向：**单价和第二名精确到小数点后四位完全相同**（价格不是它的变量）、**切换成本按天计**（AfterQuery 一天切完，71.5k star 的开源社区绑定在 2026-06 被它自己收回私有仓库了）、**最大对手的同类业务规模已是它的 6 倍**（Modal 沙箱 $300M vs 它中枢 $50M）。它现在真正拥有的东西只有一个：**在一个正在爆炸的需求上，它是跑得最快的那家**。那是一个事实，不是一道墙。

## 3. 北极星指标

- **North Star（推断）**：**每日/每月创建的沙箱数**。依据有三条：①官方和媒体披露客户时，用的单位全是沙箱数（Writer 单月 30 万、Snorkel 累计 100 万、LangChain 4,000/月），不是合同金额；②这是唯一同时领先于收入和成本的量 —— 沙箱数先涨，机时账单和机队采购才跟着涨；③定价按秒计费、无席位，所以收入 ≈ 沙箱数 × 平均存活时长 × 规格单价，沙箱数是其中唯一由客户行为驱动的因子。标为**推断**，官方未直接表述。
- **为什么是它**：席位制公司的北极星可以是席位数，因为席位先签、用量后来。按秒计费的公司反过来 —— 用量先发生、账单后结算，所以**用量就是先行指标本身**。这也是为什么官方愿意公布「月度 NRR 135%」：在这种模型里，NRR 衡量的是**同一批客户的 agent 比上个月多跑了多少次**，它是渗透深度的直接读数。
- **配套指标**：
  1. **月度净收入留存 ≈ 135%** `[官方]` —— 同一批客户每月多花 35%。这是全篇最有信息量的一个数，比 25x 更难伪造。
  2. **机队利用率** —— 决定毛利率的那个数，未公开。按上面 54% 的平衡点，这同时是它自己的生死线。
  3. **单沙箱平均存活时长** —— 未公开，但它是「有状态长时运行」这个差异化卖点的量化证据。如果客户用它只是跑 3 秒的代码片段，E2B 就够了。

## 4. AI 在业务中的作用

| 层次 | Daytona 的情况 |
|---|---|
| **AI = 产品本身** | **否，且必须说清。**产品里没有任何模型 —— 它不生成代码、不调一次 LLM API，CEO 明确说**不做推理**（「很多公司已经在做了」）。它是一台按秒出租的虚拟机。 |
| **AI = 效率杠杆** | **是，而且是主要杠杆。**约 25 人撑起中枢 $50M 的 run-rate、$1B 估值、B 轮之前近乎零销售。 |
| **AI = 营销标签** | **确有成分，但指向的是需求而非技术。**「Agent Execution Cloud」「给每个 agent 一台电脑」是叙事包装；底下是 microVM + 快照 + 调度。不过这个包装不算名不副实 —— 它描述的是客户是谁，而客户确实全是 AI 公司。 |

**这是本档第二个「产品里一点 AI 都没有、增长全部由 AI 制造」的样本**（第一个是四天前的 Blacksmith）。两者并列读很有意思：Blacksmith 站在「AI 写完代码之后要验证」这一格，Daytona 站在「AI 干活时需要一台机器」这一格，都是靠卖机时吃 AI 的外部性，都没有模型依赖。

- **用自研模型还是调 API**：都不用。**模型层依赖风险为零** —— 这是它相对本档绝大多数公司的真实优势，值得单独记一笔：它不怕 token 降价，不怕模型厂涨价，不怕 API 限流。
- **基础模型每次升级，是利好还是威胁**：**纯利好，而且是它整个投资逻辑的核心。**模型越强 → agent 敢被放手做的事越多 → 每件事要开的沙箱越多。它的风险完全不在模型变强，在模型变**便宜且集中**（见第 6 节）。
- **一个值得抄下来的宏观赌注**：CEO 的判断是会出现 **CPU 短缺**（「CPU crunch」）—— 过去两年所有人囤 GPU，但 agent「干活」用的是 CPU。他引的外部数据：AMD 把服务器 CPU 市场增速预期从约 18% 上调到 35%+/年、2030 年超 $1,200 亿；Arm 称 agentic AI 数据中心每吉瓦可能需要 **1.2 亿个 CPU 核**、是传统数据中心的 4 倍；部分服务器 CPU 交期已达 6 个月 `[媒体]`。他另外估算，Meta 的 Muse 若要服务 1 亿用户，需要 **$28 亿**的沙箱 `[估算（CEO 本人）]`。这些数字不用照抄，但**「GPU 管思考、CPU 管干活，agent 时代的瓶颈会从前者挪到后者」**这个结构性判断，是本篇最值得带走的东西。

## 5. 增长引擎

主引擎是 **自助注册的产品驱动增长（PLG）**，B 轮之前基本没有销售团队。但获客的前端打法很反常，值得单独记：

1. **线下活动，CEO 本人跑。**CEO 做过开发者大会（Shift），所以 go-to-market 几乎全靠线下场子。2026-03 它在旧金山 Chase Center 自办了第一届大会，约 **1,200 人**到场 `[媒体]`。
2. **产品还没有的时候，先买了 11 块旧金山广告牌** `[媒体]`。
3. **开源作为分发与融资杠杆**：仓库攒到 71.5k star，A 轮报道明确说开源发布帮它吸引了投资人兴趣 —— 然后 2026-06 归档转私有。拿到分发就收口，这是把开源当增长渠道而非商业模式的典型用法（好处是干净，代价是没留下社区锁定）。
4. **自下而上穿到大客户**：客户构成是「YC 早期公司 + Fortune 100」两头，CEO 称全球市值最高的五家公司里有两家是客户。自助注册先进来，企业版（SSO / 审计日志 / BYOC）再往上卖。
5. **引擎的真实来源其实在客户的客户那边**：它 2026 年的加速不是因为营销变好了，是因为**客户的 agent 用量爆了**。这是它最舒服也最危险的地方 —— 增长不用它推，但也不由它控。

病毒系数 / 渠道合作：**未公开**，无证据表明存在实质渠道。

## 6. 风险与争议

1. **单价已经完成价格发现，这一层正在商品化 —— 这是最硬的一条。**它和 E2B 的 vCPU、内存单价**精确相同到小数点后四位**。CEO 自己说市面上约有 **100 家**沙箱提供商。更要紧的是同行的公开判断：有分析直接写「沙箱层正在商品化、对大多数提供商来说自建专有沙箱是一场必输的游戏」，而 Modal 的应对是往上走、把自己定位成编排层而非沙箱竞品。**当第二名和第一名的单价一样、而第一名的规模是你的 6 倍时，你的 $1B 估值买的不是位置，是增速的延续性。**
2. **规模差距比增速差距更能说明问题（看空视角）。**Modal 2026-10 的 run-rate 是 **$1B**（同比 15x），其中**沙箱一条线就是 $300M**，累计 30 亿个沙箱、200+ 员工、20 多个云，估值 $15.75B。Daytona 中枢约 $50M。也就是说，Daytona 增速更快（25x/9 月 vs 15x/年），但在**同一个产品品类上，它只有行业第一名的六分之一**，而对方还有推理、训练、编排这些 Daytona 明确不做的业务在摊成本。「增速 > 规模」是本档的选股原则，不等于规模差六倍可以不算 —— 在一个单价相同的商品市场里，规模直接等于采购成本优势。
3. **收入分母完全不受控。**它的收入 = agent 尝试次数 × 机时单价。两个因子都在往下的方向上：推理成本每年数量级地降（agent 跑得更便宜不代表开的沙箱更多，也可能意味着客户更舍得自建），而单价已经被 E2B 钉死。如果 agent 的执行逻辑被模型厂收进自己的托管运行时（OpenAI / Anthropic 已各自提供代码执行与计算机使用的托管能力），这个分母会直接被截流一段。
4. **切换成本接近于零，而且有实证。**AfterQuery **一天之内**把自建 GKE 集群整体切到 Daytona —— 这条案例是官方当卖点讲的，但它反过来成立：**一天能切进来的东西，一天也能切出去。**客户要走只需要改 SDK 调用。加上开源仓库已归档，社区层面的绑定也被自己收回了。
5. **口径与可信度。**所有增长数字都是 CEO 口述、无第三方验证：25x 和 50.9% 来自 Fortune / Dealroom 转述的 CEO 原话；135% 月度 NRR 只有官方博客一个来源；绝对收入从未公布过一次。更需要警惕的是第 2 节的反推结果 —— **「2026-01 起 25x」这个口径的成立前提，是 2025 下半年有半年原地踏步**。只报倍数的公司，报的往往是起点最低的那个窗口。
6. **B 轮的资金结构。**$60M 里约 **$50M 来自老股东**，FirstMark 连续领投三轮（A、B）并占董事会席位。内部轮占比这么高，既可以读作「最了解数据的人加注」，也可以读作「外部新钱对这个价格不够踊跃」。两种读法都没被证据排除，但在一个单价已商品化的赛道上，后一种值得认真对待。
7. **客户集中度与客户的性质。**付费集中度**未公开**。但看名单就知道风险形状：模型厂（Anthropic、OpenAI、Meta、Nvidia）和编码 agent（Cursor、Cognition）**全都是有能力也有动机自建的主体**，而且规模越大越划得过来（见 54% 的平衡点）。它最大的客户，正好是它最可能的替代者。

## 7. 给我的启发

1. **真正的拐点往往不在产品上线那天，而在「客户的客户」改变行为那一季。**Daytona 2025-04 就上线了、95 天冲到 $3M，然后走平半年；连续 50.9% 的月增是 2026-01 才开始的。那一刻变的不是它的产品，是 RL 训练环境和后台编码 agent 同时进入生产。看一家卖铲子的公司，**先去看它下游那条曲线什么时候折的** —— 如果公司的加速点和下游的折点对不上，加速就是销售动作而不是需求变化。反过来，它当年那次「3 个月剩余跑道、关掉有收入的老产品、把客户介绍给竞争对手」的硬转向，赌的也不是自己的产品更好，是下游需求的量级不同。
2. **去抓竞品的定价页。单价相同是最快的护城河判定法。**这篇里最有信息量的三十秒，是把 Daytona 和 E2B 的定价页并排放 —— $0.0504 和 $0.0162，四位小数完全一致。任何关于「技术领先」「体验更好」的论述，在这两个相同的数字面前都要降一档读。同一个方法还能算出盈亏平衡点：售价 ÷ 自建成本 = 客户该外包还是自建的临界利用率（这里是 54%）。**一个能被算出来的临界点，就是一条能被客户算出来的离开理由。**
3. **「产品里没有 AI」可以是优点，别把它当减分项。**Daytona 和四天前的 Blacksmith 是同一类标本：零模型依赖 —— 不怕 token 降价、不怕模型厂涨价、不怕上游把功能做进产品。代价是它们完全不控制自己的收入分母。所以判断这类公司，问题不该是「它的 AI 够不够真」，而该是两个：**它收费的那个计量单位，是不是 AI 干活时无法绕过的最小颗粒**（Daytona 是：一次尝试一台机器）；以及**这个单位的单价，是不是已经被同行钉死了**（Daytona 也是）。第一个问题决定它能长多快，第二个问题决定它能守多久。这两个答案可以同时是「是」—— 那就是一家增长极快、但护城河很弱的公司，Daytona 正是如此。
