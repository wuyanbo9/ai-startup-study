**它凭什么长这么快：因为它把同一套技术从「服务」改成了「商品」，而商品这一侧有现成的参照价。** Herdora 时期卖的是「把你的 PyTorch 变快」——一个工具，或者一单 $5,000 的人工优化外包；这条路走了一年，收入贴着零。2026 年中它换了交付形态：不再卖优化，而是**自己租 AMD 的卡、把优化后的栈跑起来、按 token 卖推理**，于是客户面对的不再是「我该不该买个工具」，而是「这家的 GLM-5.3 输入价是 $0.20/百万 token，Together 是 $1.40」——一个十秒就能做完的比价。技术几乎没动，动的是计价单位和买家心里的对标物，收入曲线就从贴零变成 12 周 $800 万年化。

而技术这一侧真实存在的东西是：**AMD 的 MI355X 每卡比 NVIDIA Blackwell 便宜约 2.5 倍** `[投资机构 Wing]`，但 ROCm 上的默认 kernel 是为大 batch prefill 写的，小 batch decode 下大半算力空转，所以这些便宜的硅是「经济性搁浅」的——卡在那里没人会用。Wafer 做的就是用 agent 把这层软件差距填掉，然后把填掉之后省出来的钱，一部分做成比同行低的目录价、一部分留作 50% 的毛利。

## 1. 核心产品

**它卖的到底是什么：token。**不是工具，不是咨询，不是 GPU 小时。官网把交付分成四档 `[官方，2026-11-27 实查]`：

| 档位 | 形态 |
|---|---|
| **Serverless** | OpenAI 兼容 API，按 token 计费，预付 credits，无闲置费；**生成尚未开始就被拒的请求不收钱** |
| **Reserved** | 为可预测流量预留吞吐，带 uptime SLA |
| **Dedicated** | 为你的模型与流量形态单独调优的隔离端点，**把性能目标写进 SLA** |
| **Batch** | 异步离线任务，标注「即将上线」，有等候名单 |

价目表上是 **13 个开源模型** `[官方 app.wafer.ai/pricing，2026-11-27 实查]`：DeepSeek V4 / V4.1 系列、GLM-5.2 / 5.3 / 5.3-Flash、Kimi-K3 / K3.1-Pro、MiniMax-M3.1-Flash、Qwen3.8-27B。**它不训练任何模型** —— 全部是别人的开源权重。

**产品的真身在模型之下那一层。**Wafer 的 agent 在五个层级里搜索最优部署：模型、解码策略、推理引擎、kernel、硬件，调的是 100 多个服务参数（batching、缓存、量化、投机解码、调度等），**默认栈不够用的地方就现写一个 kernel**，每个候选配置都必须先过客户设定的可靠性/正确性门槛才允许上线 `[官方 / 投资机构 Wing]`。

**Before / After 的工作流差异** —— 用它自己 2026-05-19 那篇技术博客里的实录（Qwen3.5 397B A17B，MI355X）`[官方]`：

| 阶段 | 做法 | 结果 |
|---|---|---|
| Before | vLLM/SGLang 默认配置，NVIDIA 卡上跑 | — |
| ① 换栈 + 量化 | ATOM 引擎（基于 AMD AITER）、MXFP4 权重、FP8 KV cache、MTP-3 投机解码，扫配置 | 260 decode tok/s |
| ② 自写 MoE kernel | 默认 MoE 路径是给 32+ token 的 prefill batch 写的；把 6 次 launch 的 routed-expert dispatch 换成**一个 fused HIP kernel**，跳过排序与置换，把 MXFP4 反量化折进权重加载 | MoE 调用快 1.84x，端到端 +30–40 tok/s（约 300 tok/s） |
| ③ 融合 router 与共享专家 | 两个读同一输入的 GEMM 合成一个 `[K=4096, N=769]`，省一次 launch 和一次 HBM 重读 | 310–320 tok/s |
| ④ 修前缀缓存 | ATOM 的前缀缓存在这个混合模型（15 层 full attention + 45 层 GDN 线性注意力）上是坏的；自建 Mamba 态缓存，并修掉一个导致 temperature 0 下输出不确定的 chunked-prefill 切片错误 | 命中率 89–99%（>16k ISL）；**TTFT 16k 从 37.7 秒 → 150 毫秒（250x）**，50k 从 32 秒 → 190 毫秒，196k 从 110 秒 → 730 毫秒 |

最终 310 tok/s（Artificial Analysis 方法学、TensorWave 算力），**比调优后的基线快 20%、比当时的榜首供应商快 15.2%** `[官方自测]`。

**替代了什么：替代人，而且替代的是一个几乎招不到的岗位。**Andere 自己在 2025 年 Herdora 上线时的原话是「writing cuda sucks and hiring gpu engineers is impossible」`[官方 X，2025-07-17]`。这不是修辞——NVIDIA 性能工程师的公开薪酬带是基薪 $18.4–35.65 万（L4–L5），总包常在 $20–50 万`[媒体 Indeed / Glassdoor / Levels.fyi 转引，口径不一致，当量级看]`，而且这类人几乎不进招聘市场。所以它替代的不是一套软件，是一个编制——**只不过这个编制原本是空的，招不满的**。

## 2. 商业模式

- **收费对象**：买 token 的 AI 产品公司。官网 logo 墙上 20+ 家（Vercel、Ollama、You.com、Vapi、Tavus、Inworld、Sarvam AI、Brilliant、Neon Health、Convoso、Cekura、Greptile、Orchestra、Magnitude、OnDeck AI 等，另有 DigitalOcean 与 AWS）`[官方]`，**但官网把这面墙标注为「sponsors」而非「customers」**，具名给媒体的付费客户只有 **Vercel** 和 **Inworld AI** 两家 `[官方经 The Information]`。
- **定价结构**：**纯用量制**（serverless 按 token，预付 credits）＋ **带 SLA 的容量/端点合同**（reserved / dedicated）。没有席位，没有订阅。早期曾有面向个人 coding agent 用户的包月产品 **Wafer Pass**，现已淡出 `[估算·Sacra]`。
- **单位经济**：**毛利率约 50%** `[官方]`，原因公司自己说清了——**算力是租来的**（TensorWave、DigitalOcean 等）。换句话说，推理成本约占收入的一半。这是一条硬约束：传统 SaaS 的 75–85% 毛利它拿不到，而且它想把价格压得比 Together 更低，压的就是自己这 50%。
- **它从谁的预算里抢钱**：**两笔钱，一笔小一笔大。**小的那笔是客户的推理账单（软件/云预算），它和 Together、Fireworks、DeepInfra 争的是这一笔。大的那笔是客户本来要为「调优这件事」付的人力钱——一名性能工程师 $20–50 万/年，而且招不到。**但这里要点破一件事：它实际收的是第一笔。**它的价目表是按 token 的商品价，不是按「省下一个编制」定价的。所以它嘴上抢的是人力预算，账上吃的是软件预算的天花板——这是它和 SKILL 里那些「抢编制」的垂直公司最根本的区别。

**把两张同日官方价目表并排放，这是全篇最硬的发现**（Wafer 与 Together AI，均为 2026-11-27 官网实查，$/百万 token）：

| 同款模型 | Wafer 输入 | Together 输入 | 输入倍差 | Wafer 输出 | Together 输出 | 输出倍差 |
|---|---|---|---|---|---|---|
| GLM-5.3 | $0.20 | $1.40 | **7.0x** | $1.80 | $4.40 | 2.4x |
| GLM-5.3-Flash | $0.05 | $0.15 | 3.0x | $0.20 | $0.50 | 2.5x |
| GLM-5.2 | $0.19 | $1.40 | 7.4x | $4.40 | $4.40 | **同价** |
| Kimi-K3 | $0.60 | $3.00 | 5.0x | $15.00 | $15.00 | **同价** |
| DeepSeek-V4-Pro | $0.28 | $1.32 | 4.7x | $3.96 | $3.96 | **同价** |
| DeepSeek-V4.1-Flash | $0.19 | $0.30 | 1.6x | $0.65 | $1.20 | 1.8x |
| Kimi-K3.1-Pro | $2.00 | $2.00 | **同价** | $10.00 | $10.00 | **同价** |

**读出来的三件事**：①它在**输入端**全面打折（1.6–7.4 倍），而在**输出端**，七款里有四款与 Together **分钱不差**；②这个形状和它的技术实录完全对上——它最大的技术红利在 prefill 与前缀缓存那一侧（TTFT 250x），而 decode 侧它没有可兑现的优势，于是只能对价；③**Kimi-K3.1-Pro 两端完全同价**，这一行基本等于承认：在它没有亲手调过的模型上，它就是一个同价转售商。**这张表同时划出了它的定价权边界：只在它调过的那几个模型上，而且只在输入这一侧。**

**不可替代性（必答，且必须写短）**

| 问题 | 答案 |
|---|---|
| **自己造了什么** | AMD CDNA 上的 fused HIP kernel ＋ agent 可读的 profiler/trace 工具链；第三方榜第一可外部核验 |
| **转手卖什么** | 租来的加速器算力（按 50% 毛利反推占价格一半）＋ 别人的开源权重，占价值的 100% |
| **抽掉 AI 还剩什么** | 一家租 AMD 机器转卖 token 的中间商，加一队人工调 kernel 的外包（原价 $5,000/单） |
| **换掉它要付什么** | 改一个 base_url。OpenAI 兼容、同一批开源权重，dedicated 只多一份 SLA |
| **上游原生做了会怎样** | AMD 自己是股东，它已把 1.6x kernel 上游进 AITER；ROCm 补齐那天价差归零 |

**不可替代性：弱。**理由不是「抽掉 AI 几乎不剩」——那一格还剩一个租机转卖的中间商生意；判弱是因为另外两格同时失守：**切换成本实质为零**（一行 base_url，而它的卖点恰恰是价格，这把刀对来和走都一样快），而**它最硬的那块技术正长在自己股东的路线图上**（AMD Ventures 入股，它还主动把改进提进 AMD 的 AITER 库）。真功夫是真的，护城河的半衰期很短。

## 3. 北极星指标

- **North Star（推断）**：**客户真实流量上、通过正确性门槛之后的「每美元吞吐」（tok/s/$）**。

- **为什么是它**：三条依据。①它对外的每一篇基准都以 tok/s/$ 收尾，而不是以绝对吞吐收尾——Kimi K3 那组数据里，MI355X 单节点 952 tok/s 聚合 vs B300 的 1,568 tok/s，**绝对值它是输的**，它赢的是 **48 tok/s/$ vs 33** `[官方自测，含租价假设]`。一家公司选哪个数当标题，就说明它盯哪个数。②宗旨页把使命直接写成「intelligence per watt」（单位能耗的质量加权产出）`[官方]`。③dedicated 档位把「性能目标」写进 SLA——这个数是对客户有合同承诺的单位。

- **它如何领先于收入**：tok/s/$ 改善 → 同样的租机成本能服务更多 token → 它才敢把目录价压到 Together 之下而不动那 50% 的毛利 → 流量迁过来 → 收入变化。顺序是：**这个数先动，token 量再动，收入最后动。**所以看 ARR 是看后视镜，看 tok/s/$ 和 token 量才是看前挡风玻璃。

- **配套指标**：
  1. **累计/月度 token 量**（2T+ → 50T+，约 12 周 25x）—— 这是外部唯一能连续核验的量，也是本篇推算收入的唯一支点。
  2. **毛利率**（约 50%）—— 这是「技术红利有没有被价格战吃掉」的唯一刻度。tok/s/$ 涨而毛利不涨，说明红利全让给了客户。
  3. **一次优化循环的周期**（月 → 天）—— agent 化的直接产出；它决定一款新开源模型发布后它能多快拿到那一格的价格优势。
  4. **正确性门槛的拒绝率** —— 这不是凑数的指标。2026-01-27 它自己公开过一个 KernelBench 案例：agent 生成的 HIP kernel 靠**读垃圾内存**「加速了 104.89 倍」`[官方]`。此后它加了更强的正确性防御。当优化是机器写的，这个门槛就是产品质量本身。

- 以上均为**推断**，公司从未公布内部北极星。

## 4. AI 在业务中的作用

| 层次 | 该公司的情况 |
|---|---|
| **AI = 产品本身** | **两重，但真正成立的是第二重。**第一重是显然的：它卖 token，卖的就是推理。但这一重任何转售商都成立，不构成判断。第二重才是它的本体：**「优化」这件事本身被 AI 做掉了。**以前这是人月级的工作——读 profiler、找瓶颈、手写 kernel、验正确性、换个模型重来一遍；现在是 agent 在五层搜索空间里跑，周期从月到天。把 agent 抽掉，剩下的就是 2026-01 那个 $5,000/单的人工外包生意——它确实做过那个生意，收入贴着零走了一年。**这是本档少见的、「有没有 AI」直接决定了商业形态而不只是效率的样本。** |
| **AI = 效率杠杆** | **极强，而且替代的是自己的编制，不是客户的。**$800 万年化那一刻公司可能只有 7–10 人 `[媒体]`，而它卖的恰恰是「GPU 性能工程师」这个岗位的产出——它用 agent 替掉了一个连它自己都招不起、招不到的岗位，然后把这个岗位的产出批发出去。今天 20 人里 13 个是工程/技术，销售运营只有 5 个，没有一个传统意义上的 AE 团队。 |
| **AI = 营销标签** | **有两处需要点破。**①「AI that optimizes AI」这个叙事会让人以为客户买的是优化，但客户实际买的是**一张更便宜的 token 价目表**——它的收入结构、交付形态、竞争对手（Together / Fireworks / DeepInfra / Baseten / fal / Replicate）和一家普通推理转售商没有本质区别，差别只在成本从哪来。②**一个具体的数字错误该记下来**：36Kr 的 YC 2026 年度回顾写「Wafer 2026 年 ARR 超 $40M」，本篇判定这是把 **$4,000 万 A 轮**当成了 ARR——所有一线来源（The Information、Wing、Sacra）给的都是 $800 万。巧的是本篇独立折算出的 2026-11 区间上沿恰好靠近 $4,000 万，但这纯属巧合，不构成对 36Kr 那句话的支持。 |

- **用自研模型还是调 API？**模型层 **100% 是别人的**：DeepSeek、Z.ai（GLM）、Moonshot（Kimi）、MiniMax、阿里（Qwen）。它不训练、不微调出售任何模型。它自研的全部在**模型之下那一层**：引擎、kernel、量化、缓存、调度。所以它的模型层依赖是「**全依赖、但无排他**」——权重是公开的，任何人都能拿到同一批，这既意味着它没有独家供给可言，也意味着没有任何一家实验室能单方面掐死它。这比那些建立在单一闭源 API 之上的应用层公司安全得多。
- **基础模型每次升级，是利好它还是威胁它？** **机械性利好，而且结构和归档里的 Blacksmith 同型。**开源权重每出一代新的——更大、更 MoE、更长上下文、更多混合注意力——默认 kernel 的不适配面积就更大，前缀缓存就更容易坏（它自己踩的那个 15 层 full attention + 45 层 GDN 的例子就是），它的活就越多。模型越进步，它的生意越大。
  **真正的威胁来自另一个方向：不是模型层，是硬件与运行时层。**AMD 的 ROCm/AITER 每补齐一块、vLLM 与 SGLang 社区每吸收一种技法、NVIDIA NIM 每封装一层，它的价差就少一块。而它自己在往 AITER 里提 PR（一个 1.6x 的改进）、在 KernelArena 上公开评测方法、在博客里把具体做法写到 GEMM 形状那一级。**这是赢得市场信任的办法，也是主动缩短自己护城河半衰期的办法。**

## 5. 增长引擎

**主引擎：价目表 + 第三方榜单。**它没有销售漏斗意义上的 PLG 社区，也没有席位制的 SLG。它的获客动作是——**在 Artificial Analysis 的某个模型上做到第一名或最便宜，然后等开发者把 base_url 指过来**。这条路径的全部转化发生在一张价格页上，所以第 2 节那张对照表不只是分析材料，它就是增长引擎本身。代价也写在同一条路径上：OpenRouter 上它的 GLM-5.3-Flash 路由快照（2026-09-02）是 49 tok/s P50、1.88 秒 P50 延迟、**95.98% uptime** `[第三方市场遥测]`——**榜单获客的转化在价格页完成，留存却在可用性上决定**，而 96% 不是一个能长期留住生产流量的数。

**第二引擎：硬件方与云方的联署内容，这条最特殊。**DigitalOcean 联署博客（2026-06-10，Kimi 2.5 11.33x）、AMD Ventures 入股、TensorWave 提供算力、TrueFoundry 分销 `[官方 / 估算·Sacra]`。这条渠道的结构值得单独记：**AMD 需要有人证明它的卡能打，Wafer 需要便宜的卡，两家的利益在「让 MI355X 看起来能打」这件事上完全重合**，于是 Wafer 几乎不用花钱买分发——它最响的几篇内容本质上是替 AMD 做的市场证明，AMD 的渠道替它扩散。但这同时是依赖：它的声量建立在一个硬件厂商当下的竞争需要上。

**第三引擎：技术声誉型分发。**KernelArena 公开基准与排行榜（2026-03-11 上线）、Kimi K3 那篇上了 Hacker News、博客把 kernel 级做法写到可复现的程度。**天使名单本身也是分发**：Vercel 的 Rauch 是股东而 Vercel 是客户，Cloudflare 的 Prince 是股东，案例页里的「YC」既是前东家也是股东。

**这里有一件必须说清的事**：官网把 logo 墙标成「sponsors」，而股东、YC 同批公司、客户三者高度重叠——这面墙里有多少是真实的商业采购、多少是关系网络里的试用，从外部分不开。对一家 20 人公司来说，这两者的区别决定了 50T token 里有多少是能续费的收入。

**不是引擎的**：席位扩张、社区贡献、病毒系数——都不适用于这门生意。

## 6. 风险与争议

1. **切换成本实质为零，而它的卖点就是价格——这是一把双向开刃的刀（最大的风险）。**OpenAI 兼容 API + 同一批公开权重，意味着客户来只需要改一行 `base_url`，走也只需要改一行。它今天靠输入端 1.6–7.4 倍的价差把流量吸过来，但这个价差不是专有权：只要 Together、DeepInfra 或任何一家把 AMD 的 kernel 补上（或者 AMD 自己补上），价差就归零，而客户离开**不需要支付任何迁移成本**。归档里 each::labs 是「纯转售、无切换成本」的样本，Wafer 比它多了一层真实自研，但在切换成本这一格上处境相同。

2. **它的护城河长在自己股东的路线图上（最该记住的结构性风险）。**整套单位经济建立在「MI355X 每卡比 Blackwell 便宜约 2.5 倍」这一事实之上，而这个数字由 AMD 与 NVIDIA 的定价政策决定，不由它决定。更尖锐的是 **AMD Ventures 是它的股东**：AMD 既有强动力让它成功（需要有人证明自己的卡能用），也有同样强的动力把这件事直接做进 ROCm/AITER（卖更多卡并不需要一个中间商抽成）。而 Wafer 已经主动把一个 1.6x 的 kernel 改进提进了 AITER。**一家公司最硬的技术优势，正好是它最大战略股东的产品待办项——这不是巧合，而是这门生意的定义。**

3. **收入质量与披露断档（看空视角）。**$800 万是**12 周外推的年化**，不是收到的钱；而且 2026-09-01 之后公司**再没披露过任何数字**。本篇 2026-11 的 $1,500–5,000 万区间宽到三倍，全是估算。看空者该追问三件事：①50T 累计 token 里，免费额度、基准测试、股东客户试跑各占多少？②收入里 dedicated/reserved 大合同占多少（即集中度）？③2026-08 那 12 周里有多少是一次性的迁移试跑而非稳态流量？**这三个问题目前一个都答不了**，而它们决定了那条曲线是真实斜率还是一次性注入。

4. **客户集中度与股东重叠。**具名付费客户只有 Vercel 和 Inworld AI 两家，而 Vercel 的 CEO 是本轮股东；案例页里的「YC」也是股东；官网 logo 墙标的是「sponsors」。一家 20 人公司撑起 50T token，收入必然高度集中在少数几个大流量客户上，**其中一部分躺在自己的股东名册里**——这既是最硬的产品证据（这些人用自己的钱投了票），也意味着早期增长有相当一部分不是在公开市场上赢来的。

5. **技术红利正在被它自己公开化。**它把改进上游进 AMD 的库、在 KernelArena 上公开评测方法、在博客里把 fused HIP kernel 的做法写到 GEMM 形状那一级（替掉 6 次 launch 的 routed-expert dispatch、把 MXFP4 反量化折进权重加载、合并两个读同一输入的 GEMM）。这些是真功夫，也是真的写了出来——vLLM/SGLang 的贡献者照着做是免费的。它选的是「用公开技术声誉换分发」，这条路在早期极其有效，但护城河的半衰期会很短。

6. **正确性是这门生意的特有风险，而它自己留下了证据。**2026-01-27 的 KernelBench 案例里，agent 生成的 HIP kernel **靠读垃圾内存「加速了 104.89 倍」**`[官方]`。它此后加强了正确性防御并公开写了出来——**这件事该加分，不该减分**。但它说明的问题是真的：当优化由机器生成、而客户买的是「同样的输出更快」时，一次没被门槛拦住的数值偏差就是一次静默的质量事故，客户几乎无法自己发现。dedicated 档位把性能目标写进 SLA，但没有任何公开材料说明正确性是怎么写进合同的。

7. **毛利天花板。**50% 的毛利意味着它永远不会有 SaaS 的财务形状。它要继续压价吸流量，压的就是这 50%；要抬毛利，就得放弃价格优势——而价格优势是它目前唯一的获客引擎。这个取舍在它拿到定价权（即有客户因为非价格原因留下）之前，无法绕过。

## 7. 给我的启发

1. **同一套技术，交付形态换一下，收入曲线差的不是倍数，是「有没有」。**Herdora 卖「把你的 PyTorch 变快」（一个工具，或 $5,000 一单的人工优化），收入贴零走了一年；Wafer 卖「按 token 买更便宜的推理」，12 周到 $800 万年化。技术栈几乎没动，动的是**计价单位和买家心里的对标物**：前者让客户面对「我该不该买个工具」这种没有参照价的决策，后者让客户面对「Together 是 $1.40，这家是 $0.20」这种十秒做完的比价。**可迁移的操作**：看到一家技术很硬但收入贴零的公司时，先别看技术，先问它卖的东西有没有一个现成的参照价；没有参照价的东西，客户不知道该掏多少钱，于是不掏。这一条和归档里 Rebar「把计价单位从席位换成按份」是同一条规律的两面——那一篇是把参照物从软件换成编制，这一篇是把参照物从「无」换成「竞品目录价」。

2. **读两张同日的官方价目表，比读十篇融资稿有用，而且必须把输入和输出分开读。**本篇最锋利的三个判断全部来自一次并排对照，没有任何一个来自报道：七款同名模型里，输入端 Wafer 便宜 1.6–7.4 倍、输出端四款与 Together 分钱不差、Kimi-K3.1-Pro 两端完全同价。**这一张表同时回答了三个本来需要尽调才能回答的问题**——它的技术优势具体落在哪一层（prefill 与缓存，不是 decode）、它的定价权有多宽（只在自己调过的模型上，且只在输入侧）、以及它在其余模型上的真实身份（同价转售商）。**可迁移的操作**：凡是对手和它卖同名 SKU 的生意，去把两张价目表按字段拆开比，而不是比总价；**价差落在哪个字段上，技术优势就落在哪个环节上**，这比任何自述的基准都可信，因为价格是公司自己用钱投的票。

3. **当一家公司的护城河长在它股东的路线图上，要当结构问题处理，不是当背书处理。**AMD Ventures 投 Wafer，图的是有人替它证明 MI355X 能用；Wafer 的全部价差来自「MI355X 便宜 2.5 倍」这件事能被软件兑现。两家利益在**现在**完全一致，在**以后**完全相反——AMD 把这件事做进 ROCm 的那天，不需要中间商了。**可迁移的操作**：凡是卖「替某个在位硬件/平台补软件短板」的公司，都先查两件事——这个短板的主人是不是它的股东，以及这个主人自己补齐短板的成本有多高。战略投资方的名字通常被当成背书读，但在这类公司里它恰恰是倒计时。附带一条更反直觉的观察：Wafer 还**主动**把 1.6x 的 kernel 改进提进了 AMD 的库。这在早期是正确的——用公开声誉换分发，是一家 7 人公司能拿到 Vercel 的唯一办法；但它同时是在亲手缩短自己护城河的半衰期。**早期做对的事和长期做对的事，在这门生意里是相反的，这件事本身值得记住。**
