# CodeRabbit —— 把「AI 写码的排泄物」做成收费站

## 📈 增长快照（先看这个）

| 项目 | 数据 |
|---|---|
| 成立时间 | **2023 年初** `[媒体]`。不是从零开始：创始人 Harjot Gill（宾大博士，Netsil 创始人，2018 年卖给 Nutanix）当时在做可观测性公司 FluxNinja，看到开发者用 Copilot 后代码产出暴涨、审查堵住，于是 2023 年初开了 CodeRabbit 并把 FluxNinja 整个折进来 `[媒体]`。联合创始人 Gur Singh。总部旧金山 |

**它凭什么长这么快**：它卖的东西，是上一波繁荣的**排泄物**。

官方自己把因果链写得很直白：用 Copilot、Claude Code、Cursor 的开发者，「提交的 PR 数量涨了 2 到 3 倍」`[官方，2025-09 B 轮博客]`。代码生成的成本塌了，而审查的成本没塌——审查是一个人读懂另一个（或另一个 agent）写的东西，这件事的单位成本仍然是一个资深工程师的一小时。于是整个行业在 2025 年同时长出了同一个瓶颈：**PR 队列**。CodeRabbit 不生产代码，它在这条突然变长的队列上收费。Groupon 的公开案例是「review 到上线从 86 小时压到 39 分钟」`[官方]`。

这个位置有三个结构性好处，值得单独点破：

1. **它的需求量不是自己创造的，是 Cursor、Copilot、Claude Code 替它创造的**。这是本档少见的「需求外生」型公司——它不需要教育市场，市场被别人用几十亿美金教育完了。
2. **计价单位藏得很聪明**：只对「开过 PR 的开发者」收费 `[官方定价页]`，不是按仓库成员数，也不是按 PR 数。装的时候不痛（一个五十人的组可能只有二十个人真的开 PR），用起来会自然长。
3. **冷启动是免费开源**：10 万+ 开源项目在用 `[官方]`，GitHub 与 GitLab 上装机量第一 `[官方]`。第一批真实流量来自日本——zenn.dev 上有人自发写了 50 多篇文章介绍它，没人找他们写 `[媒体]`。C 轮当天宣布的 $10M 开源承诺，本质是把这个漏斗买下来。

但第 2 条同时是这门生意最大的裂缝，下一节会拆开讲：**它按人收钱，按 PR 花钱**。

## 1. 核心产品

**卖什么**：一个挂在 pull request 上的 AI 审查员。装成 GitHub / GitLab / Azure DevOps / Bitbucket 的 App，PR 一开，它拉全仓上下文、跑 40 多个 linter 与 SAST 工具、再用前沿模型在有问题的行上留评论，并给一键修复 `[官方]`。2026-08 的 C 轮把产品线扩成三块：Triage（按价值/紧急度/风险给 PR 打分排队）、Change Stack（看一个改动在系统级的波及面）、Security（对生产代码持续扫漏洞），合起来叫「Agentic Change Management」`[官方]`。

**用户在什么场景打开它**：不打开。它是常驻的——PR 一开自动跑，开发者在 GitHub 的评论区里见到它。这是一个**没有自己界面的产品**，好处是零学习成本，坏处见第 2 节。

**替代了什么**：

| | Before | After |
|---|---|---|
| 谁看这个 PR | 同组另一个工程师，排队等他有空 | 三分钟内先过一遍机器 |
| 看多久 | 队列 86 小时（Groupon 案例） | 39 分钟 `[官方]` |
| 看什么 | 人肉读 diff + CI 里一堆互不说话的 linter 报告 | 全仓上下文 + 40 多个工具的结论去重后合成一条条可执行评论 |
| 漏什么 | 人会累、会放行熟人的代码 | 机器不累，但会吵（噪声是这个品类的头号死因） |

注意它**没有替代人**：Copilot 的审查在 GitHub 上算 Comment 不算 Approve，CodeRabbit 同理，protected branch 上还是要人点同意 `[媒体]`。所以它抢的是**软件预算里的一条**，不是人力预算——这一点直接决定了天花板，见下节。

## 2. 商业模式

- **收费对象**：工程团队自己。自助买单为主（ACV 只有约 **$2,900**：$50M ÷ 17,000 客户 `[估算]`），再往上卖 Enterprise（Adyen、BMW、Indeed、JFrog、NVIDIA `[官方]`）。这是一条彻头彻尾的 bottom-up PLG 曲线，不是企业直销。
- **定价结构**：纯席位制，按「**开过 PR 的开发者**」计费，年付 `[官方定价页，2026-09-29 取]`：

| 档 | 年付 | 月付 | 关键差异 |
|---|---|---|---|
| Free / OSS | $0 | — | 公开仓库无限用 |
| Essentials | **$24**/人/月 | $30 | 审查、一键修复、learnings、5 个 MCP 连接 |
| Team | **$48**/人/月 | $60 | + 自定义合并前检查、补单测、解冲突、post-merge |
| Advanced | **$72**/人/月 | $90 | + 波及面分析、架构影响分析、每个 PR 的安全审查、持续安全监控 |
| Enterprise | 面议 | — | SSO、RBAC、审计日志、**自托管**、SLA |

  **2026-06-08 它把 $12 的 Lite 档和 Pro Legacy 档下线了** `[官方知识库]`，同时在顶上加出 $72 的 Advanced。一升一砍，起步价一年之内从 $12 变成 $24——**当期收入增长里有一部分来自提价，不是全部来自客户增长**，而公司不披露 NRR，这一部分无法拆开。

- **单位经济**：**毛利率从未披露**，但可以从两头夹出一个区间。收入端：$50M ÷（2M 次/周 × 52 周）≈ **$0.48/次审查** `[估算]`——分母含免费开源，所以付费侧的实际单价高于此，但免费那部分推理是实打实烧掉的。成本端有一个漂亮的外部锚：Cursor 在 2026-06-08 把 Bugbot 从 $40/席位改成**按次 $1–1.5 一个 PR** `[媒体]`。也就是说，市场上另一家的挂牌单价，高于 CodeRabbit 的推算综合单价。这不是效率优势，这是**定价单位的错配**：

  > **它按人收钱，按 PR 花钱。** AI 每多替一个开发者写一倍的代码，这个开发者的席位费一分不涨，而他触发的推理次数翻倍。

  这家公司的需求来自「AI 让每个人的 PR 产出涨 2–3 倍」，而它的收入公式里**没有 PR 这一项**。它博的是席位数（开 PR 的人数）涨得比人均 PR 数快。这个假设在人写码的时代成立；在 agent 自己开 PR 的时代，方向是反的。它博客里那句「as more employees and AI agents generate code」，把 agent 和员工并列成席位增长的来源，但定价页写的是「只对开 PR 的开发者收费」——agent 开的 PR 记在谁头上，目前没有公开答案。这也解释了为什么 2026-06 要砍掉 $12 档。

- **它从谁的预算里抢钱**：**软件预算**，而且是软件预算里最拥挤的那一格（开发者工具）。天花板因此低一个数量级——对照本档抢人力预算的 Legora（律师工时）、Retell AI（离岸坐席）。$24–72/人/月 这个价带，跟 GitHub Copilot Business 的 $19/人/月 是同一条线上的邻居，而那 $19 里**已经含了一个 code review** `[媒体]`。

**不可替代性（必答，且必须写短）**

| 问题 | 答 |
|---|---|
| **自己造了什么** | 40 多个 linter/SAST 的编排与去噪层、四大 Git 平台的 PR 通道、可自托管部署。模型不自研。 |
| **转手卖什么** | 前沿模型推理。它自己按月发 Claude Sonnet 5.5 / Opus 5.5 / GPT-6 的横评，谁强换谁——成本占比未披露。 |
| **抽掉 AI 还剩什么** | 一个挂在 PR 上的 linter 聚合器加审计留痕，即 2015 年的 SonarQube。 |
| **换掉它要付什么** | 卸一个 GitHub App、删一个 yaml。累积的 learnings 会丢，一个季度内可重建。 |
| **上游原生做了会怎样** | 已经在做：GitHub 2026-03 把 review 做成 agentic 并含进 $19 的 Copilot Business；Cursor 买下 Graphite。 |

**不可替代性：弱。** 理由不是「竞争激烈」，是三件可验证的事叠在一起：切换成本可以用两个动作清零；质量差距已经收敛到测不出来（Martian 的 Code Review Bench 上前五名挤在 4 个百分点内，CodeRabbit 约 59.6% `[第三方]`）；而托管着 PR 的那个平台，把同一个功能放进了一个更便宜的、客户已经在付的订阅里。

它手上确实有两样别人没有的东西，但都不是护城河级别的：**跨平台**（GitLab / Bitbucket / Azure DevOps 上 GitHub 原生的方案够不着）和**独立性叙事**（让写代码的那家去给自己的代码打分，等于让被审计方出审计报告——这是它对企业最有力的一句话，也是 C 轮稿的主题词「independent review and governance infrastructure」）。这两条能守住一部分金融、汽车、制造业客户（Adyen、BMW、NVIDIA 在列），但守不住那 17,000 家自助客户的基本盘。

## 3. 北极星指标

- **North Star（推断）**：**每个 PR 上被开发者真正采纳的评论数**（评论 → resolved/commit 的转化率）。官方未披露任何内部指标，这是从产品死因倒推的：AI 审查员的唯一死法是「太吵」——一旦一个团队开始习惯性地折叠它的评论，这个席位在下一个续费日就没了，而在此之前 ARR 上看不出任何异常。采纳率是唯一一个在收入变化前几个月就会松动的数。
- **为什么是它**：席位制 + 自助 + 零切换成本 = 流失是静默的、逐个团队发生的。周审查量（2M/周）是他们对外讲的数，但那是分母不是分子——免费开源项目也在里面，跑得越多越烧钱。真正领先于收入的是分子。
- **配套指标**：① 付费席位中「本月开过 PR 的人」占比（计费口径就是这个，掉下去直接掉收入）；② 周活跃仓库数 / 客户数（渗透深度）；③ NRR——**公司从不披露，这是估值上最大的一块空白**。

## 4. AI 在业务中的作用

| 层次 | CodeRabbit 的情况 |
|---|---|
| **AI = 产品本身** | **是。** 抽掉 LLM，剩下的是一个 linter 聚合器——那个东西 2015 年就有，叫 SonarQube，卖不上 $24/人/月。「拉全仓上下文、读懂意图、逐行解释为什么这样不对」这一层只有模型能做。 |
| **AI = 效率杠杆** | **基本没有。** 263 人做 $50M，人均 $190K，和一家普通 devtools 公司一模一样。它不是那种「50 个人做 $100M」的故事。 |
| **AI = 营销标签** | **少量。** 「Agentic Change Management」这个词是 C 轮包装出来的品类名，底下的三个模块（Triage / Change Stack / Security）是实的，但把它讲成一个新品类，是为了从「PR 上的机器人」这个 $19 就能买到的位置上挪开。 |

**自研还是调 API**：**全部调 API**，而且调得很公开——官方博客按月发模型横评（2026-09-22 Opus 5.5、2026-09-28 Sonnet 5.5、2026-09-04 GPT-6 Astra），逐个比「多抓了多少、漏了什么、多贵、多快」。这是诚实的工程文化，也是一份写给所有人看的**供应商依赖清单**。

**模型升级对它是利好还是威胁**：**短期利好，长期威胁，而且是同一件事的两面**。模型每强一档，它的审查质量免费涨一截、成本免费降一截——这是它 2025 年那条 10x 曲线的一半原因。但同一次升级也让「在 PR 上做一次高质量审查」这件事变得任何人都能做：Martian 的 Code Review Bench 上，前五名（Cubic、Codex、Claude/Cursor、CodeRabbit 约 59.6%、Greptile 约 59.5%）挤在 4 个百分点内 `[第三方]`。当差异测不出来，剩下的竞争维度就只有分发和捆绑——而这两样它都不占。

## 5. 增长引擎

主引擎是**开源免费 + 平台商店的默认位**，不是销售。

1. **冷启动靠日本**。第一波真实用户来自 zenn.dev，有人自发写了 50 多篇文章，公司没有找过任何一个作者 `[媒体]`。创始人说正是这个信号让他决定把它做成公司。
2. **开源当分发**。10 万+ 开源项目免费用，直接推高 GitHub / GitLab Marketplace 的装机排名，成为「AI 应用里装机第一」`[官方]`。开发者在开源项目里见过它，回到公司装私有仓库——这是一条无需销售的转化路径。C 轮当天宣布的 **12 个月 $1,000 万开源投入** `[官方]`，就是把这条路径明码标价买下来。
3. **计费口径本身是增长设计**。只对开 PR 的人收费，装机时不用跟财务解释为什么全组要买。
4. **企业侧靠自托管与跨平台补位**。BMW（同时是 C 轮投资人 BMW i Ventures 的关联方）、Adyen、NVIDIA、JFrog 这类客户买的是 GitHub 原生方案给不了的东西：GitLab/Bitbucket 支持、自托管、审计日志、RBAC。
5. **病毒系数的真实来源**：机器人的评论直接出现在公开仓库的 PR 页面上，每一条都是一次曝光。这是典型的「产品即广告位」，但也意味着**质量事故同样是公开的**。

## 6. 风险与争议

1. **计价单位与成本单位错配（最结构性的一条）**。按人收费、按 PR 花钱。它的整个需求故事是「AI 让每人的 PR 产出涨 2–3 倍」，而这个倍数**不进它的收入，只进它的成本**。$0.48/次的推算综合单价对着 Cursor Bugbot $1–1.5/次的挂牌价，说明它现在是在用低于市场挂牌的隐含单价换装机量。2026-06 砍 $12 档、加 $72 档，是第一次公开的调价动作；如果毛利健康，没必要这么早动价格表。

2. **平台把它做进了订阅里**。GitHub 的 Copilot code review 在 2026-03-05 转为 agentic 架构并 GA（会读全仓上下文，不只是 diff），含在 $19/人/月的 Copilot Business 里 `[媒体]`；2026-09-01 起还能直接 approve PR `[官方 GitHub changelog]`。Cursor 在跨过 $1B 年化后收购了 Graphite（上一轮估值 $290M，成交价「远高于」）`[媒体]`，并把 Bugbot 改成按 PR 计价。**托管代码的平台和生成代码的工具，从两头同时进了这个房间。** 它的反击是「独立性」——写代码的不该给自己打分——这个论证对合规行业有效，对 17,000 家自助客户基本无效。

3. **收入口径存在公开冲突，且 NRR 全黑**。同一时点上，Sacra 给 $50M（2026-08），而 getlatka、startups.center 一类的估算站给 $15M（2026-09）`[第三方]`——差 3.3 倍。公司在官方稿里只说「同比 5x+」，从不给绝对数，也从不给 NRR。在一个切换成本≈0、ACV≈$2,900 的自助盘子上，NRR 是唯一能区分「真扩张」和「涨价 + 新客盖住流失」的数，而它恰好是缺的那个。30x 的估值倍数是在没有这个数的前提下给出的。

4. **增速已经掉了一档**。2025 年约 10x，2026 上半年年化约 2.4x。这个减速发生在 GitHub 原生化和 Cursor 收购 Graphite 的同一个半年里。$1.5B / $50M = 30x 这个倍数，需要 ARR 到 $75–100M 才回到「正常」区间 `[第三方分析]`；若增速停在 2x 附近，按常规软件 10–15x 定价，对应的是 $500–750M —— 也就是回到它 B 轮的位置。

5. **质量差异已经测不出来**。Martian Code Review Bench 上前五名差距不到 4 个百分点。当一个品类的头部产品在盲测里分不出高下，定价权就从产品转移到分发方——而分发方是 GitHub。

6. **看多的一条（为公平起见）**：如果「AI 生成代码的合规与治理」真的变成一个受监管的门类（像 SOX 之于财务、像审计独立性之于会计），那么「生成方不得自审」会从一句营销话变成一条硬要求，CodeRabbit 现在这个位置就会突然变得不可替代。它的 C 轮叙事整个押在这一条上。这是一个**关于监管而不是关于技术**的赌注。

## 7. 给我的启发

1. **找上一波繁荣的排泄物，但先检查自己的计价单位有没有跟着它涨。** CodeRabbit 的选址堪称教科书——它不跟 Cursor 抢代码生成，它在 Cursor 的产出端收费，需求完全外生，几十亿美金的市场教育别人替它做了。但它把计价单位定在「人」上，而它接住的那个洪水的单位是「PR」。位置对了，刻度错了。这一条和 Numeral 那篇是同一个病灶的两个病例（交易量涨 4 倍、按申报次数收费所以收入不动），建议两篇对照读：**选址决定你能不能长，计价单位决定你长的是收入还是成本。**

2. **当你的产品运行在别人的平台上、而那个平台的订阅里已经包含了一个同类功能，你的估值倍数定价的是叙事，不是切换成本。** 30x 给的是「AI 代码治理会变成独立品类」这个故事。检验它只需要一个问题：**买家会为「审查方与生成方不是同一家」这件事本身多付多少钱？** 在受监管行业答案是正数，在其余地方接近零。这个问题在 SaaS 时代叫渠道风险，在 AI 时代它换了个名字叫捆绑风险，但算法一样：把你的功能从平台自带的那个版本里减掉，剩下的那部分就是你真正卖的东西。

3. **增速换挡比增速本身信息量大得多。** 「同比 5x+」是一句真话，也是一句把两条斜率完全不同的曲线揉成一个数的话。10x 那一年的市场结构和 2.4x 这半年的市场结构，中间隔着 GitHub 的一次原生化和 Cursor 的一次收购。**读到任何一个「同比 Nx」，都要问它跨越了几个季度、以及最近那个季度单独是多少**——一家公司真正的处境写在最新那一段斜率里，不写在年度倍数里。
