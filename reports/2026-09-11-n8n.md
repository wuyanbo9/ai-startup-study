**它凭什么长这么快？**

先说清楚它**不是**什么：它不是 2023 年后冒出来的 AI 新公司。n8n 2019 年就在做一件很不性感的事——开源的工作流自动化，说人话就是「自托管版 Zapier」：把 Gmail、Postgres、Slack、Salesforce 这些系统用可视化节点连起来，带重试、日志、版本控制，而且可以装在自己机房里。这门生意做了五六年，收入不到 $10M。

转折点是 2022-2023 年 Jan 把三个人关进去干了六到八周，把 LLM 和 agent 做成了**节点**。这个动作的杠杆不在「加了 AI 功能」，而在于**它把自己所在的品类从「SaaS 之间搬数据」换成了「AI agent 落地的唯一必经之路」**。

原因是 agent 这东西在 demo 里只需要一个模型，在企业里需要的是别的：它得读到 ERP 里的真实数据、得写回 CRM、得在出错时重试、得留下谁在什么时候调了什么的日志、得在没有出口网络的环境里跑、还得让审计过得去。**模型厂商给的是大脑，这些是手脚和病历本。**n8n 恰好已经有了 1500 个接口、一个带重试和日志的执行引擎、和一个可以装进防火墙内的部署形态——这些东西 2019 年就在造了，只是当年不值钱。

所以曲线的形状是：**存量资产 × 新需求**。这是本档里少见的一种增长来源——前面分析过的公司大多是需求和产品一起新建，n8n 是需求突然搬到了它已经建好的房子门口。看它 80% 工作流带 agent 这个数字就知道，用户不是来做 Zapier 那种事的。

要泼的冷水也在这里：**它最大的分发资产（开源社区版，自托管、执行次数无限、免费商用）同时是它最大的价值泄漏口**。170 万月活构建者里绝大多数一分钱不付，付钱的是 1400 家需要 SSO、Git 版本控制和 SLA 的企业。它卖的其实不是能力，是合规。第 6 节细说。

## 1. 核心产品

**卖的东西**：一个工作流引擎。画布上拖节点连线，每个节点是一次动作（读邮件、查数据库、调模型、发消息、调 MCP server），连成的图叫 workflow，跑一次叫一次 execution。有触发器（定时、webhook、事件），有分支和循环，有错误处理和重试，有执行历史。2026-01 的 2.0 版本把 LangChain 原生集成进来，带约 70 个 AI 节点，并且加了**「agent 调某个工具前必须人工批准」**这种给企业用的闸门 `[媒体]`。

**谁在什么场景下打开它**：不是产品经理，是**公司里那个会写一点代码的人**——平台工程师、IT、运维、增长工程师、以及大量的自动化外包/咨询团队。场景是「我们有个 agent 的想法，但它得能读我们的系统」。

**Before / After：**

- **Before（两条路，各有各的死法）**
  - **买 Zapier / Make**：上手快，但按「任务」计费、逻辑复杂就画不动、代码只能塞进受限的沙箱、**不能装在自己机房**——对欧洲的银行、保险、医院、以及任何数据不能出境的场景，这一条直接判死刑。
  - **自己写脚本**：能力无上限，但写出来的是一次性的。没有重试、没有执行日志、没有权限和凭据管理、没人接手、出问题只能翻服务器日志。三个月后没人敢动它。
- **After**：用一个引擎把两条路的中间地带占了——**画布给你快，代码节点给你无上限，自托管给你合规，执行历史给你可运维**。工作流本身是 JSON，可以进 Git、可以 code review、可以在 dev/prod 两套环境之间发布。

它替代的是什么？**既不是人也不是软件，是「集成这件事本来要自己搭的那套底座」。**这和本档里 Sierra（替代客服坐席）、Retell（替代离岸坐席）那类抢人力预算的公司不是一回事——n8n 抢的是**工具预算 + 内部平台团队的自建预算**。天花板因此低一档，这点后面不能含糊。

## 2. 商业模式

- **收费对象**：三层。① 个人开发者和小团队买云订阅（信用卡自助）；② 企业 IT / 平台团队买自托管 Business 或 Enterprise 许可（要的是 SSO/SAML、Git 版本控制、环境隔离、日志外送、外部密钥库、SLA）；③ **OEM/嵌入**——SAP 这类把 n8n 装进自己产品里卖的伙伴，按执行量年度承诺付费。第三方拆的收入结构约为 云 55% / 企业许可 30% / 嵌入 15% `[估算，二手]`，官方未公布。
- **定价结构**（官方定价页，2026-09-11 抓取）`[官方]`：
  - **Starter €20/月**（年付）：2,500 次执行/月，云托管
  - **Pro €50/月**：10,000 次执行/月，含 admin 角色、工作流历史
  - **Business €667/月**：40,000 次执行/月，**支持自托管**，SSO/SAML/LDAP、Git 版本控制、多环境
  - **Enterprise 询价**：执行量自定，200+ 并发、365 天洞察、外部密钥库、日志流、带 SLA 的专属支持
  - 关键设计：**所有套餐不限用户数、不限工作流数，只按「整条工作流跑一次」计费，一次执行里有 3 步还是 300 步、调 1 次模型还是 100 次模型，都算一次。**
- **单位经济**：毛利率**官方未公开**，第三方给的口径是 75%+ `[估算，二手]`。这个数字比多数 AI 应用公司体面，原因很实在——**推理账单大部分不由它承担**：自托管客户填自己的 API key，模型钱直接付给 OpenAI/Anthropic/自建；云版虽然送「AI credits」，但那是引流额度不是主要用法。**它卖的是编排，不是 token。**这一点让它和 Higgsfield、Baseten 那种毛利被上游吃掉的模式有本质区别。
- **它从谁的预算里抢钱**：抢的是 **iPaaS/集成软件预算**（Zapier、Make、MuleSoft、Workato 那条线），外加**内部平台团队的自建预算**——就是「我们本来要派两个工程师维护一堆胶水脚本」的那笔钱。参照价是清楚的：一个集成/平台工程师在欧洲一年 $80–120K，而 Business 版一年约 $8.7K。**但注意：这仍然是软件预算的量级，不是 Sierra、Retell 那种直接砍坐席的人力预算。**

## 3. 北极星指标

- **North Star（推断）**：**「进入生产的工作流实例数」**——更精确地说是「连续 30 天以上有执行记录、且挂着 agent 节点的工作流数」。官方未披露内部指标，这是从三处反推的：① 计费单位是执行次数，收入是它的直接函数；② 公司对外反复引用的两个数是月活构建者（170 万）和带 agent 的工作流占比（80%+），而不是客户数；③ 招聘页把目标写成「$1B ARR、少于 500 人」，这种目标只可能建立在自助放量上，不是销售线性堆出来的。
- **为什么是它领先于收入**：这门生意的漏斗是 **装上社区版 → 画出第一条能跑的工作流 → 从玩具变成生产任务 → 要 SSO / 要审计 / 要 SLA → 付钱**。付费发生在最后一步，但决定付费的是第三步。一条工作流一旦扛上了真实业务（比如每天处理进来的订单邮件），它就从「有趣」变成「停不得」，采购只是时间问题。所以生产工作流数的变化会比收入早一到两个季度。
- **配套指标**：① **执行量的净增长**（客户内部渗透的直接证据，也是 OEM 合同的计价基础）；② **社区版 → 付费的转化率与转化时长**（官方从未披露，这是外部最该追问的一个数）；③ **企业客户的执行量扩张率**（Trendyol 1000+ 用户、700 条工作流、Stepstone 向 3000 名员工铺开，这类案例是净留存的代理指标）`[媒体]`。

## 4. AI 在业务中的作用

| 层次 | n8n 的情况 |
|---|---|
| **AI = 产品本身** | **一半是。** 没有 AI，n8n 依然存在——它 2019 年就存在，只是六年只做了不到 $10M。AI 不是它的产品，是**它服务的那个需求**：80%+ 工作流里跑着 agent。准确的说法是「没有 AI 这产品还在，但这家公司不值 $5.2B」 |
| **AI = 效率杠杆** | **是，而且是罕见的强。**「$1B ARR / <500 人」这个目标本身就是宣言；产品里也有 AI 生成工作流。当前人均创收按 250 人推算约 $440K，是 Zapier（约 $220K）的两倍 |
| **AI = 营销标签** | **有一点。** 「AI orchestration platform」的叙事让一个 iPaaS 拿到了 47x 的倍数，而同品类的 Zapier 上一轮是 $5B 配 $310M 收入（约 16x）。市场为「agent 时代的管道」这个故事付了约 3 倍溢价 |

**自研还是调 API**：全部调 API，且**刻意不碰模型层**。它不训练模型，不托管模型，甚至不强制你用它的 key——自托管客户填自己的。这是一个重要选择：**它主动放弃了 token 差价，换来了中立性和 75%+ 的毛利。**在本档里这是少数「模型涨价跌价都跟我关系不大」的公司。

**基础模型升级对它是利好还是威胁**：**短期显著利好，长期是一条正在逼近的边界线。**利好在于模型每强一分，值得接进企业系统的 agent 场景就多一批，而每一个场景都要一条工作流。威胁在于模型厂商正在往编排层走（agent 构建套件、托管工具调用），并且工具调用越可靠，中间那层「人工编排的图」就越可能被模型自己替代——终局是「你只需要描述目标，模型自己决定调什么」。n8n 的挡箭牌是**跨系统 + 自托管 + 审计**：模型厂不愿意也不方便去接一家德国保险公司机房里的 SAP。这块挡箭牌真实，但不会永远这么宽。

## 5. 增长引擎

主引擎只有一条：**开源分发 + 内容飞轮**，销售是后装的。

1. **开源即渠道**。204K GitHub stars、60.6K forks。工程师不需要跟任何人说话就能把它装起来跑通——这是它能从柏林起步却在全球铺开的唯一原因。对照 Zapier 的 1400 人，n8n 的获客成本结构完全不同。
2. **模板与教程的内容生态**。9000+ 官方模板，加上 YouTube/Reddit 上体量惊人的第三方教程——「用 n8n 搭一个 XX agent」在 2025-2026 年几乎成了 AI 自动化教学的默认载体。这里有一个别人难复制的细节：**教学内容本身需要一个能截图、能一步步演示的可视化产物**，代码框架（LangGraph 之类）在这个媒介上天然吃亏。
3. **自动化外包/咨询团队当二传手**。大量小型 AI 自动化机构拿 n8n 给客户交付，等于一支不拿工资的销售队伍——这和 Clay 靠代理机构生态铺开是同一个套路。
4. **自下而上再到 IT**。工程师先自托管跑起来，业务变重要后 IT 介入，要 SSO 和审计，转成 Business/Enterprise。**销售的工作不是说服客户用，是给已经在用的客户开发票。**
5. **2026 年新增的第五条：OEM 嵌入**。SAP 把 n8n 装进 Joule Studio，意味着 n8n 可以搭着 SAP 的企业销售队伍进大客户。这是从社区分发切换到渠道分发的第一步，也是估值从 $2.5B 跳到 $5.2B 的直接原因。

## 6. 风险与争议

1. **免费版就是完整版，付费买的是合规——这决定了定价权的上限。** 社区版自托管、执行次数无限、允许内部商用，功能覆盖约 95%。付钱的理由集中在 SSO/SAML、Git 版本控制、多环境、日志外送和 SLA。这意味着：**每当客户觉得贵，退路是现成的**，代价只是失去审计功能。一家靠合规差价赚钱的公司，毛利很好，但很难提价。官方从不披露社区版到付费的转化率——这恰恰是最该被追问的数字。
2. **执行数计费与客户价值不挂钩，而且没有缓冲。** 一次执行可能调用 100 次模型，也可能只是收了封空邮件，账单一样。2026 年最集中的用户抱怨是**执行额度跑满后工作流直接停摆、没有超额付费选项、要等下个计费周期**；有测评指出一个 Gmail 轮询的工作流能在 11 天内耗光 Starter 的 2500 次额度 `[媒体]`。计费口径和用户感知价值脱节，长期会推高流失或逼客户跑去自托管——**而自托管的尽头是不付钱。**
3. **47x 的倍数押的是「agent 需要人工编排」这个前提。** 这个前提正在被模型能力侵蚀：工具调用越可靠、上下文越长，「先画一张图再让模型按图走」的必要性就越低。n8n 2.0 的应对是往企业治理（人工批准、环境隔离、审计）走，这是对的方向，但也说明**它的护城河正在从「好用」迁移到「合规」**——后者利润稳定，想象力有限。
4. **SAP 既是渠道也是风险。** 估值翻倍的直接原因是 SAP 嵌入 Joule Studio。但 SAP 自己有 Build Process Automation，历史上从不缺把合作方能力内化的先例；而且渠道收入的质量低于直销——**它是被别人的销售周期决定的收入**。这笔嵌入合同占收入多少、期限多长，均未披露。同时 SAP 买的是老股，钱没进公司，这一轮不代表公司账上多了 $60M。
5. **数字口径要打折看。** 全篇最关键的两个数都不干净：**一是收入**——$40M、$70M、€100M 分别来自 Sifted/PitchBook、Sacra 和媒体转述，公司本身从未发过一篇「我们到了 $100M ARR」的官方博文，唯一的官方表述是 C 轮那句「收入 10x」；**二是人数**——第三方抓取给出 140 到 1189 的离谱区间，所有人均创收计算（包括本文的 $440K）都建立在一个没被证实的分母上。读到这类数字时请把它当区间，不要当点估计。
6. **看空视角，一句话版本**：这是一家**用开源做分发、用合规做收费闸门的 iPaaS**，赶上了 agent 落地这波浪。它赚的每一分钱，本质上是企业为「把 AI 关进自己机房并留下日志」付的过路费。这条路真实存在且会长期存在，但它是一条**管道生意**——管道生意的历史估值区间是 10–20x 收入（Zapier 上一轮约 16x），而现在市场给了 47x。差额买的是「agent 时代的默认编排层」这个身份。这个身份能不能坐稳，取决于两件它控制不了的事：模型会不会把编排自己吃掉，以及微软会不会用 Copilot Studio 把这层白送。

## 7. 给我的启发

1. **「AI 让一个旧品类突然涨价」是一类独立的机会，而且比「AI 造新品类」更容易被低估。** n8n 的引擎、节点库、自托管形态全是 2019–2023 年造的，当年它们只值不到 $10M。变的不是资产，是需求搬到了资产门口。所以看公司时要多问一句：**这家公司增长这么快，是因为它新建了什么，还是因为它六年前建的东西突然变得稀缺了？**后者的护城河通常更硬——因为对手要补的是时间，不是判断力。
2. **放弃 token 差价，可能是 AI 应用公司最值钱的一个决定。** 本档里毛利被上游吃掉的案例已经不少（Higgsfield、Retell 的 gross 口径问题）。n8n 反过来：不训模型、不托管模型、甚至让客户自带 key，代价是放弃了一块收入，换来的是 75%+ 毛利、模型涨价免疫、以及在客户眼里的中立性。**当你的价值是「连接」，就不要顺手去卖被连接的东西。**
3. **开源分发的真实成本，是你永远拿不到定价权，只能拿到合规溢价。** 社区版免费无限用，付费买的是 SSO 和 SLA——这个结构带来了极低的获客成本和 170 万构建者，也同时锁死了提价空间：任何涨价都会把客户推回免费版。这是一笔明确的交易，不是免费午餐。判断这类公司时，要盯的不是 GitHub star 数，而是**从免费到付费的转化率和转化时长**——而这恰恰是这类公司最不愿意披露的数。没披露，就按最保守的假设算。
