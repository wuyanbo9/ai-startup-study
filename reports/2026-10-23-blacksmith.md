**它凭什么长这么快 ——** 因为它卖的计量单位，正好是 AI 写代码这件事的副产品。AI 编码代理每多开一个 PR，CI（持续集成：代码合并前自动跑的构建与测试）就要多跑一遍全套构建和测试；代理不但写代码，还帮着审代码、改代码、重跑失败的测试，于是瓶颈从「写」整体移到了「验证」。这不是推测，上游最大的那家自己写了出来：Anthropic 2026-09-14 的工程博客说它的 CI 作业量**六个月涨 25 倍**、测试数量约 10 倍、80% 的合并代码由 Claude 写、工程师单季代码产出约 8 倍 `[官方（Anthropic）]`。Blacksmith 站的就是这条曲线的下游一格 —— 它不生成一行代码，不调一次大模型 API，它只是把跑这些作业的机器按分钟租出去，9 个月里周作业量从 500 万涨到 9,000 万。**这是本档第一个「增长完全由 AI 制造、而产品里一点 AI 都没有」的样本**，也因此它是检验「抽掉 AI 还剩什么」这个问题的反向标本：抽掉 AI 叙事，它剩下一门完整的生意；抽掉 AI 需求，它的曲线立刻折平。

## 1. 核心产品

**卖什么**：GitHub Actions 的 runner（跑 CI 作业的那台机器）替代品。客户把工作流文件里的一行 `runs-on: ubuntu-latest` 改成 `runs-on: blacksmith`，作业就从 GitHub 自己的机器挪到 Blacksmith 的裸金属机队上跑，其余一切不变 —— 流水线定义、密钥、日志界面、权限模型都还在 GitHub 里。

**什么场景下打开它**：没人「打开」它。它是一次性接入、之后隐形的基础设施，工程师感知到的只有「CI 等待时间变短了」和「月底 GitHub Actions 账单变小了」。

**Before / After**：

| | Before | After |
|---|---|---|
| 跑在哪 | GitHub 托管 runner（云虚拟机，通用型 CPU），或自己在 AWS 上搭 self-hosted runner | Blacksmith 的专用裸金属机队，每台 32 vCPU 消费级「游戏 CPU」，一个作业一个 Firecracker microVM `[官方]` |
| 为什么慢 | 云虚拟机单核性能一般，且 CI 作业的负载是「又短又尖」—— 一次 push 触发几十个作业、几分钟后全部消失，而超大规模云厂商的 VM 开机速度跟不上这种突发 `[官方]` |
| 缓存 | GitHub 原生缓存与 Docker 层缓存要重新下载 | 持久化 Docker 层缓存与 sticky disk 挂在本地 NVMe 上，官方称缓存下载快 4x `[官方]` |
| 存储成本的真相 | 超大规模云把网络挂载存储和 VM 捆在一起：2TB io2 EBS 约 **$3,850/月** | 2TB 消费级 NVMe **买断不到 $200** `[官方，2025-05]` |
| 自建的代价 | 要么过量预配（机器闲着烧钱），要么让工程师排队等 runner `[官方]` |

**替代的是什么**：替代**软件 + 机器**，不替代人。它不减少任何一个工程师，它减少的是工程师等 CI 的时间和 GitHub 的账单。客户自己给的数字：Ashby GitHub Actions 成本降 75%、部署频率翻倍；VEED 部署快 2x、成本降 70%；Clerk 成本降 70%；Supabase 测试时间减半；Mintlify 构建快 2x；Devsisters 构建快 1.5–2.5x `[官方（客户案例页）]`。

**2026 年新开的第二条线**：Sandboxes（beta）—— 把同一套「全功能 VM + 环境快照」卖给跑编码代理的团队，官网明确说它适合「卡在构建与测试时间、而不是卡在推理时间」的代理，不适合要亚秒级冷启动的场景 `[官方]`。这等于把 CI 机队的同一批机器复用给 agent 执行环境，直接撞上本档的 Modal 和一众 agent 沙箱。

## 2. 商业模式

- **收费对象**：工程组织的 CI / 开发工具预算。不是人力预算 —— 这一点决定了它的天花板比本档那些「替掉一个编制」的公司低一个数量级，但客户决策链也短得多（改一行 YAML，不用过采购）。
- **定价结构**：纯用量制，按分钟计费，无席位 `[官方，2026-10 定价页]`：

| 机型 | 单价 | 官方称相对 GitHub 的总成本节省 |
|---|---|---|
| Ubuntu x64 | **$0.004/分钟** | 67% |
| Ubuntu ARM | **$0.0025/分钟** | 75% |
| Windows x64 | **$0.008/分钟** | 60% |
| macOS M4 | **$0.08/分钟** | 35% |

  每个机型含 **3,000 免费分钟/月**。加购项：Docker 层缓存 +$0.50/GB/月、sticky disk +$0.50/GB/月、静态 IP +$100/IP/月。Enterprise 档不公开价，含 99.9% SLA、7×24 支持、专属 Slack、白手套接入 `[官方]`。注意那个「节省 67%」是**两个数相乘**来的：单价便宜约 33%，再乘上官方自称的「快 2x」。

- **单位经济 —— 这家公司自己把它算给你看了**。2025-05-13 CEO 亲笔的《How the economics of multitenancy work》把毛利直接写成机队平均利用率的函数 `[官方]`：

| 平均机队利用率 | 毛利率 |
|---|---|
| 10% | 约 35% |
| 20% | 约 70% |
| 35% | 85%+ |

  机器是**租的**（原文：leased for a fixed period），**有没有客户都要付钱**。需求有硬性的昼夜与周次节律：周末用量约为工作日的 1/5，UTC 日的前 8 小时是低谷，下午（美国时区上线）是峰值；非美国客户填的是低谷，所以能在不加机器的情况下抬毛利 `[官方]`。这意味着它的毛利不是一个常数，而是一条要靠**全球客户时区拼图**和**调度器装箱效率**同时撑起来的曲线 —— 它 2026-09 的工程博客承认旧调度器下机队利用率「经常掉到 70% 以下」（指活跃期装箱效率，不是 24×7 均值）`[官方]`。

- **ARR 反推（公司只给倍数，这里给两条独立路径）** `[估算]`

  **路径 A，从作业量推**：周 90M 作业 × 52 ≈ 46.8 亿作业/年。官方说「多数 CI 作业跑 5–40 分钟」（2025-05 口径），但作业量涨 18 倍后结构必然向大量碎小作业倾斜（矩阵式并行、代理触发的重跑）。取**平均计费 3 分钟、平均 4 vCPU**（即 $0.008/分钟）→ 约 **$112M**；取平均 2 分钟、2 vCPU（$0.004/分钟）→ 约 **$37M**。

  **路径 B，从电力容量推（上限校验）**：近 10 MW。一台 32 vCPU 消费级平台含存储、网络与数据中心侧开销按约 450W 折算 → 约 **22,000 台、约 64 万 vCPU**（与它自己披露的「单个 deployment 设计目标 ≥30,000 台 / 约 100 万 vCPU」同一量级，互为交叉验证）。64 万 vCPU × 525,600 分钟/年 = 3.36×10¹¹ vCPU·分钟；按 $0.004/分钟/2vCPU 即 **$0.002/vCPU·分钟** 的目录价，满载是 $673M/年。代入它自己文章里用的示例利用率：**10% → 约 $67M，20% → 约 $134M**。

  两条路径交叉后取 **$40M–$120M、中枢约 $70M**。再用官方那个 17x 回切：2026-01 的 ARR 约 **$2.4M–$7M**。**这一步算出来的东西比 ARR 本身更有意思**：B 轮在 2026-03 成交、估值 $550M，对应的 ARR 就在 $3–8M 区间，即**约 70–180 倍**；C 轮 $1B 对应中枢 $70M，即**约 14 倍**，按下沿 $40M 也只有 25 倍。**七个月内，同一家公司的收入倍数从三位数压到十几倍。** 这不是估值下跌（估值翻了倍），是分母跑得比分子快，而市场给这门生意的定价越来越像基础设施、不像软件 —— 和本档 Prime Intellect 的 10x、Manus 的 20x→8x、micro1 对 Mercor 的 10–13x vs 28x 是同一个现象的第四次出现。

  注：近 10 MW 更像数据中心侧的签约容量口径，不等于已部署机器的实时功耗；它又明确说在「为 2027 年扩 5 倍」做准备，所以当下真实平均利用率大概落在它自己文章里那个 10% 的示例附近，而不是 35%。

- **ARPU 与集中度**：$70M ÷ 10,000+ 组织 ≈ **$7K/组织/年** `[估算]`，但每个机型每月送 3,000 分钟，长尾里必然有大量零付费账号。所以真实付费客户数远少于 10,000、真实付费 ARPU 显著高于 $7K —— 而这两个数一个都没公开，**客户集中度因此完全不可见**。

- **它从谁的预算里抢钱**：抢的是 **GitHub Actions 的账单**，外加一点自建 runner 的云账单。这是软件/云预算，不是人力预算 —— 并且更尴尬的是，这笔预算的**价目表在竞争对手手里**（见下表最后一格）。

**不可替代性（必答，且必须写短）**

| 问题 | 答案 |
|---|---|
| **自己造了什么** | 裸金属 CI 调度器、一作业一 microVM、持久层缓存。真自研，但三家竞品都有同类。 |
| **转手卖什么** | 租来的机器时间。$0.004/分钟里主成本是机架租金与电费。 |
| **抽掉 AI 还剩什么** | 剩一门完整的按分钟租机器生意 —— 产品里本来就没有 AI，AI 在需求侧。 |
| **换掉它要付什么** | 改 YAML 一行 `runs-on`。缓存和 sticky disk 重建约一天。 |
| **上游原生做了会怎样** | GitHub 已降价最多 39% 且自己就是 runner 供应商，33% 的价差随时能被抹平。 |

**不可替代性：弱。** 理由必须说清楚是哪一条压下来的：**不是**因为「抽掉 AI 就不剩什么」（恰恰相反，它抽掉 AI 剩的东西最完整），而是因为**切换成本只有一行 YAML、自研的三样东西 Depot 和 Namespace 都有、而它赖以生存的那个价差由 GitHub 的价目表单方面决定**。2026-01-01 GitHub 把托管 runner 降价最多 39%（Linux 2 核 $0.008 → $0.006/分钟）`[官方（GitHub changelog）]`，一次降价就把 Blacksmith 的单价优势从约 50% 压到约 33%；而苏黎世的 Namespace 计划内价报 **$0.002/分钟**，只有 Blacksmith 的一半 `[媒体]`。

要立刻补一句，否则这个结论会被误读：**护城河弱 ≠ 生意差**。这是本档第一个「护城河弱、但需求曲线极硬」的组合 —— 它的资产不在锁定客户，在于它比对手更早、更重地买下了算力（近 10 MW，对手总融资才 $65M 和 $15M）。这类生意赢在**产能和价格领先**，而不是赢在客户走不掉；代价是它必须永远领先，一停就被比价。

## 3. 北极星指标

- **North Star（推断）**：**平均机队利用率**（average fleet utilization）。依据是它自己 2025-05 那篇文章 —— 全文的论证结构就是「毛利 = 利用率的非线性函数」，并给出 10%/20%/35% 三档对应 35%/70%/85%+ 的毛利 `[官方]`。机器成本是固定的，收入是浮动的，所以这家公司内部唯一值得天天盯的那个数，就是「这些已经在付电费的 vCPU，有多少比例真的在跑客户的作业」。ARR 是这个数的结果。
- **为什么它领先于收入**：利用率先变，收入后变。新客户接入先表现为低谷时段被填满（毛利先升），再表现为需要加机器（成本先升、收入后升）。反过来，流失也先表现为峰值削平而不是账单归零 —— 因为按分钟计费，客户可以只切走一半作业，账面上还是个活跃客户。
- **配套指标（推断）**：
  1. **周 CI 作业数** —— 它唯一肯公开的增长指标，也是最贴近「AI 写了多少代码」这条外部曲线的代理变量。
  2. **每作业计费分钟数** —— 这个数越低产品越好、单作业收入越少。**它和收入方向相反**，是这门生意的内在矛盾（见第 6 节）。
  3. **缓存命中率** —— 决定了「快 2x」这个卖点能不能兑现，也直接决定每作业分钟数。
  4. **非美时区客户占比** —— 它自己点明这是不加机器就能抬毛利的唯一办法。

## 4. AI 在业务中的作用

| 层次 | 该公司的情况 |
|---|---|
| **AI = 产品本身** | **不是，而且差得很远**。主链路上一次大模型 API 都不调。它卖的是机器分钟、调度器和缓存。它的官网自我介绍是「the fastest way to run your GitHub Actions」和「CI cloud」，**没有一句把自己说成 AI 公司**。 |
| **AI = 效率杠杆** | 部分成立但别夸大。30 人管近 10 MW、每天 1,000 万作业，靠的是系统工程（调度器、microVM、ClickHouse 日志平台、Tailscale 网络）而不是 AI 替人。真正跟 AI 相关的内部动作是把 CI 机队复用成 agent 沙箱（Sandboxes beta）。 |
| **AI = 营销标签** | **反向错配，本档首见**：媒体给它贴的标签是「AI code-validation startup」，公司自己不贴。**这一次是外界比公司更 AI。** 对读者的意义：看到「AI 创业公司」这个词，先问它是 AI 做的产品，还是 AI 带来的需求 —— 两者的估值逻辑完全不同。 |

- **自研还是调 API**：既不自研模型也不调 API。它自研的是**硬件-软件栈**：裸金属机队、Firecracker microVM、调度器、缓存层、日志平台。
- **模型层依赖风险**：**接近零** —— 本档最低的一档（另一家是 Augmodo）。
- **基础模型升级是利好还是威胁**：**纯单边利好，而且是本档最直接的一例**。模型越强 → 代理写的代码越多、开的 PR 越多 → CI 作业越多 → 它卖的分钟越多。Anthropic 那篇文章（CI 六个月 25x）本质上就是它的需求预测报告。
- **但真正的上游不是模型厂，是 GitHub**：协议（Actions 工作流格式与 runner 协议）、生态（客户的权限、密钥、日志都在 GitHub 里）、定价（它的价差锚在 GitHub 的价目表上）三重依赖。**判断这家公司的风险，看 GitHub 的 changelog 比看模型发布会有用得多。**

## 5. 增长引擎

**主引擎是 PLG，而且是摩擦系数被压到接近物理下限的那一种。**

1. **接入成本 = 改一行 YAML + 装一个 GitHub App**。没有数据迁移、没有流水线重写、不动密钥、不换界面。这是它能在 9 个月里从 6,000 组织涨到 10,000 组织的机械原因 —— 也正是第 2 节里「换掉它只要一行 YAML」的同一枚硬币的另一面：**让客户进来有多容易，让客户走掉就有多容易。**
2. **每机型 3,000 免费分钟/月**：小团队可以长期白用，所以客户数（10,000+）和付费客户数之间有一道没人知道多宽的缝。
3. **工程师口碑 / 技术博客**：逆向 GitHub Actions 缓存、Docker 构建缓存的物理学、如何 SSH 进 Actions、用 ClickHouse 做日志平台，以及**公开故障复盘**（2026-07-21 的宕机、2026-08-13 美西机房制冷失效）`[官方]`。对卖给工程师的基础设施，公开复盘的信任溢价高于任何市场投放。
4. **YC + 创始人网络**：YC W24；创始人来自 Cockroach Labs 与 Faire，种子轮的天使里有 Cockroach 的 CEO 与 CTO、Guilded 创始人、T3 Chat 的 Theo Browne `[官方]`。早期 logo（Clerk、Ashby、Supabase、Mintlify、Finch）几乎都是开发者工具圈内部客户 —— 这个圈子互相抄 CI 配置。
5. **向上扩张靠用量自然发生**：按分钟计费意味着客户不需要重新采购，PR 变多账单自动变大。所以它的净收入扩张不靠销售，靠客户自己用 AI 写更多代码。

**渠道归属风险**：所有流量的入口在 GitHub 的 marketplace 和 Actions 生态里。这条引擎跑得快，但钥匙孔不在它手上。

## 6. 风险与争议

1. **它的两个卖点都不由它定价，而且正在两头被挤。** 卖点是「快 2x + 便宜 33%」。但：（a）GitHub 2026-01-01 把托管 runner 降价最多 39%，Linux 2 核从 $0.008 降到 $0.006/分钟 `[官方]` —— 单价优势从约 50% 被压到约 33%；（b）Namespace 计划内价 $0.002/分钟，只有它一半，且刚在 2026-10-05 拿到 Scale Venture 领投的 $42M B 轮，官方口径收入 12 个月 8x `[媒体]`；Depot 2026-03 拿了 Felicis 领投的 $10M A 轮 `[媒体]`。同赛道还有 WarpBuild、RunsOn、BuildJet、Ubicloud、Actuated。**这是一个连「快」和「便宜」都能被第三方逐分钟做成对比表的市场**（已经有一堆比价站在做了），比价摩擦接近零。

2. **估值倍数的压缩比增速更值得记。** B 轮 2026-03 成交、$550M 估值，对应当时反推的 $3–8M ARR，即约 70–180x；C 轮 $1B 对应中枢 $70M，即约 14x（按下沿 $40M 也只有 25x）。**七个月，倍数从三位数到十几倍。** 17x 的增速没有换来倍数扩张，只换来估值翻倍 —— 市场给「卖机器时间」这件事的定价，正在从软件口径滑向基础设施口径。本档第四次见到这个现象。

3. **收入口径全是估算，分母是个黑箱。** 公司三轮融资公告、全部博客、全部媒体报道里都没有一个 ARR 绝对值；连 C 轮官方博客都只写「17x」。连第三方报道都在抱怨这一点（runtimewire 2026-10-22：ARR 未披露、节省基准未展开，使这门生意的经济性「更难评估」）。本篇所有收入数字请带着 `[估算]` 的限定引用。客户集中度同样为零披露。

4. **定价与产品方向自相矛盾 —— 这是结构性的，不是暂时的。** 它按分钟收费；而它自己 2025-12 那篇文章明确写道，在 GitHub 新定价下客户「剩下的主要省钱杠杆就是减少 CI 分钟」，并把更快的 CPU、持久层缓存、容器缓存当成实现手段 `[官方]`。**产品做得越好，每个作业的收入越低。** 收入只有在作业数增长快于单作业分钟数下降时才上升。过去 9 个月作业数 18x、ARR 17x，两者基本同步 —— 说明单作业收入大致没变。一旦 AI 产出的 PR 增速放缓，这个剪刀差会立刻咬进收入。

5. **需求是二阶导数，而最大的需求方正在教所有人怎么少跑 CI。** 这条最该看空：Anthropic 那篇让它故事成立的文章，主题其实是**如何靠 test impact analysis（只跑受影响的测试）把暴涨的 CI 压回去** —— 文中描述服务被打补丁三次，三个补丁分别撑了 70 天、29 天和不到一天，最后被重写。换句话说，**行业对「CI 作业量爆炸」的标准反应不是多买机器，而是少跑作业**。Blacksmith 赚的是前一种反应的钱。

6. **它已经承担机房级风险，但只有 30 人。** 近 10 MW、租期固定的机器「有没有客户都要付钱」（它自己的话），还要在 2027 年扩 5 倍。两次公开故障里有一次是美西机房制冷失效（2026-08-13），这类风险和软件 bug 不是一个量级。30 人、$125M 融资去扛一个跨美欧的多机房资产池，一次长时间区域性故障对一门「切换成本等于一行 YAML」的生意，后果不是道歉博客能覆盖的。

7. **那个被推迟的 $0.002。** GitHub 原定 2026-03-01 对 self-hosted 与第三方 runner 的全部 Actions 用量加收 $0.002/分钟平台费，后来**推迟且未给新日期**，并把这 $0.002 折进了自家托管价里 `[官方（GitHub changelog）]`。一旦恢复，Blacksmith 客户的实付就变成 $0.004 + $0.002 = $0.006/分钟，**和 GitHub 自家托管价持平**，整个「便宜 33%」的叙事当天归零，只剩「快 2x」。这颗钉子现在挂在 GitHub 手里，随时可以钉下来。

## 7. 给我的启发

1. **判断一家公司是不是 AI 受益者，看它的计量单位，不看它用没用模型。** Blacksmith 一行 AI 代码都没有，却可能是本档对「AI 写代码」这件事暴露最纯的标的 —— 因为它的收费单位（CI 作业分钟）与 AI 的产出量（PR 数量）是机械正比关系。反过来，一堆自称 AI 的公司，收费单位是席位，和 AI 产出量无关。**找「计量单位挂在 AI 产出量上」的生意，比找「产品里有 AI」的生意更有效。**

2. **增速解决不了倍数压缩。** 17x 的 ARR 增速，换来的是从 ~100x 到 ~15x 的倍数压缩。本档已经第四次看到同一结构：Prime Intellect 10x、Manus 20x→8x、micro1 10–13x vs Mercor 28x、Blacksmith ~100x→~15x。共同点不是增速不够，是**生意形态被重新归类了** —— 当收入的主体是转手卖出去的机器时间，市场迟早会按机器的倍数给它定价，不管曲线多陡。看一家公司时，先问「它的收入里有多少是转手的机器钱」，这个比例决定了倍数的上限。

3. **当你的「更快」和「更便宜」都写在上游的价目表里时，你的护城河就是上游的耐心。** GitHub 一次降价，把 50% 的价差压成 33%；一个被推迟的 $0.002/分钟，能让这个价差一夜归零。这不是 Blacksmith 做错了什么 —— 做对了的部分（真自研的调度器、真买下的 10 MW）恰恰是它现在能领先的原因。但要分清：**产能领先和护城河是两种不同的东西**。前者需要你每年继续花钱买，后者不需要。一家靠前者赢的公司，融资节奏停不下来 —— 它十周内连融两轮、并计划 2027 年把算力扩 5 倍，不是因为钱好拿，而是因为这门生意的赢法要求它必须一直买。
