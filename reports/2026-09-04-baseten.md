**它凭什么长这么快：** Baseten 的增长本质上不是它自己的增长，而是**它的客户名单的增长**。Series F 公告里列的客户是 Cursor、Notion、Lovable、Harvey、HubSpot、OpenEvidence、Abridge、Decagon、Parallel `[官方]` —— 这份名单里有一半是本归档里已经写过的第一梯队公司。当 Lovable 在 14 个月内做到 $500M、OpenEvidence 一年涨 6 倍时，它们烧掉的推理量就是 Baseten 的收入。这是 AI 浪潮里独一份的位置：**卖铲子给正在挖到金子的人，而且是按挖出来的量收费。**

具体到这一年为什么是 20 倍而不是 3 倍，有三件事同时发生：(1) 2025 下半年到 2026 年，大批 AI 应用从 demo 转入生产，负载从「每天几万次」变成「每天几亿次」，而生产级推理的难点（冷启动、并发抖动、跨云调度、延迟 SLA）恰好是自建团队最容易低估的部分；(2) 开源权重模型（DeepSeek、Kimi、GLM、GPT-OSS 等）在代码补全、Agent、语音这些高频场景上够用了，应用公司有了「不调闭源 API，自己托管开源模型」的动机，而托管这件事本身就是 Baseten 的产品；(3) 它是**用量制**——客户不需要重新做采购决策，流量涨了账单自动涨，收入曲线的斜率直接等于整个 AI 应用层的斜率。

代价也写在同一组数字里：用量涨 40 倍、收入只涨 20 倍，说明每次调用的价格掉了一半。这是一门**要靠量的增长跑赢价格的下滑**的生意。

## 1. 核心产品

**卖的是什么：** 一个专门跑推理的云。客户把一个模型（自己微调的、开源权重的、或者多模型串起来的流水线）交给 Baseten，Baseten 给回一个能扛生产流量的 HTTP 端点，并负责这个端点背后的一切：选哪种 GPU、跨 18 家云调度容量、冷启动优化、自动扩缩容、可观测性、99.99% 可用性 `[官方]`。产品线分四块 `[官方]`：

- **Dedicated Inference**：托管客户自己的自定义/微调模型，按 GPU 分钟计费；
- **Model APIs**：Baseten 预优化好的开源模型，按 token 计费（2026/05 公开发布）；
- **Training**（2026 年推出，Loops SDK）：多节点微调任务，训完可以一键推到生产端点；
- **Baseten for Model Labs**：给模型实验室做分发和变现的渠道。

部署形态有三种：Baseten 托管、部署进客户自己的 VPC（self-hosted）、混合（自有容量 + 溢出到 Baseten 的弹性容量）`[官方]`。它还维护开源模型打包框架 **Truss**。

**用户在什么场景下打开它：** 一家 AI 编程公司的自动补全模型 p95 延迟从 200ms 涨到 900ms，用户开始抱怨；一家医疗 AI 公司在早上八点问诊高峰时段并发翻 5 倍，自建的 K8s 集群扩不上去；一家做语音的公司发现 GPU 空转成本吃掉了一半毛利。他们打开 Baseten，不是为了「用 AI」——他们本来就在做 AI——而是为了**不用自己雇一个八人的推理基础设施团队**。

**Before / After：**

- **Before**：招 3–8 个懂 CUDA / TensorRT / Kubernetes 的基础设施工程师（旧金山全成本每人每年约 $30–50 万），自己跟云厂商谈 GPU 配额，自己写批处理和 KV 缓存优化，自己扛半夜的 on-call。或者：直接调闭源大模型 API，接受它的价格、它的限流和它的模型选择权。
- **After**：写一个 Truss 配置推上去，端点当天上线；GPU 容量从 18 家云里自动找；账单按分钟走，闲下来自动缩容。团队回去做产品。

**替代的是什么：** 主要**替代自建团队 + 自己拼装的云资源**，其次替代**闭源模型 API 的一部分调用量**（Baseten 的 Model APIs 定价号称比 OpenAI 同档低 50% 以上 `[媒体]`）。它不创造新需求——推理需求本来就存在，是这波 AI 应用自己长出来的。

## 2. 商业模式

- **收费对象**：AI 应用公司的**工程/基础设施预算**，付款人是 CTO 或平台团队负责人。注意这跟本归档里大多数公司不同：Sierra、Retell、Legora 抢的是客户的人力预算，Baseten 抢的是**客户的云账单 + 基础设施工程师工资**。它的客户本身是创业公司，预算来自 VC 的钱。

- **定价结构**：纯用量制，两条计价线 `[官方]`：

  | 计价方式 | 单价 `[官方，2026/09 定价页]` |

  | 专用部署 · B200 (180GB) | $0.16633/分钟 = 约 $9.98/GPU·小时 |
  | 专用部署 · A100 (80GB) | $0.06667/分钟 = 约 $4.00/GPU·小时 |
  | 专用部署 · L4 / A10G | $0.01414 / $0.02012 每分钟 |
  | Model API · GPT-OSS 120B | $0.10 / $0.50 每百万 token（输入/输出） |
  | Model API · DeepSeek V4 Flash | $0.13 / $0.26 每百万 token |
  | Model API · GLM-5.3 | $1.40 / $4.40 每百万 token |

  套餐分三档：Basic $0/月纯按量；Pro 有量价折扣、高需求 GPU 优先配额、专属 Slack 支持；Enterprise 定制 SLA、支持自托管与混合部署 `[官方]`。**训练用同一套 GPU 单价。**

- **单位经济（这是全篇最该警惕的地方）**：Baseten **不拥有任何数据中心**，它跨 15–18 家云租 GPU 再转售 `[媒体]`。把它的挂牌价跟公开的租赁价并排看：

  | | 每 H100·小时 |
  |---|---|
  | Baseten 挂牌价 | 约 $6.50 `[官方]` |
  | 新型 GPU 云（Lambda / CoreWeave 按需） | 约 $3.99 / $4.76 `[媒体，2026]` |
  | 竞价/市场型（RunPod / Vast.ai） | 约 $1.49–1.99 `[媒体，2026]` |
  | 超大云按需 | 高至约 $6.98 `[媒体，2026]` |

  也就是说，**采购成本占最终售价大约 30–65%**，取决于它拿到什么价、以及最关键的一个变量——**利用率**。推理业务必须常年预留热容量来保证延迟，客户流量低谷时 GPU 空转的钱是 Baseten 自己出。同赛道的 Fireworks AI 毛利率约 50% `[媒体]`，2026 年 AI 公司毛利率的普遍区间是 50–60%，而不是 SaaS 的 70–80% `[媒体]`。**Baseten 未公开毛利率，但结构上不可能是软件毛利。**22 倍收入的估值倍数，如果按毛利算，实际是 40 倍以上的毛利倍数。

  另一个被 H100 价格暴跌放大的问题：2024Q4 到 2026 年初 H100 租赁价跌了 64–75% `[媒体]`。上游降价对转售商是双刃剑——进货便宜了，但客户也在拿这个价来压你。「用量 40x、收入 20x」这组官方数字，就是这场价格战在报表上的样子。

- **它从谁的预算里抢钱**：**软件 + 云预算，加一小块工程师人力预算**。这比抢人力预算的公司天花板低一档，但赛道本身在爆炸性变大——Fireworks $800M（2026/05）、Modal $300M（2026/05）、Baseten $600M（2026/03）`[媒体]`，三家加起来一年多出十几亿美元，钱是从超大云厂商和闭源 API 的口袋里挪过来的。

**不可替代性（必答，且必须写短）**

| 问题 | 答案 |
|---|---|
| **自己造了什么** | 跨 18 家云的容量调度层、冷启动与 KV 缓存优化、Truss 打包框架、99.99% SLA 的运行时。软件是真的，但不含硬件。 |
| **转手卖什么** | GPU 时长。H100 挂牌 $6.50/时，公开租赁价 $1.5–4.8/时，采购成本约占售价 30–65%。 |
| **抽掉 AI 还剩什么** | 一家跨云 GPU 转售商 + 一套运维软件。生意本体是「代运维的算力批发零售」，不是模型。 |
| **换掉它要付什么** | 重写 Truss 配置、重调延迟与扩缩容参数、重接监控、重谈容量。以工程周计，不是月。**低。** |
| **上游原生做了会怎样** | 上游是云厂商和模型实验室。AWS/GCP 把托管做顺，或开源模型都出官方托管 API，中间这层就被压薄。 |

**不可替代性：中。** 理由：软件层是真自研且现在确实比自建强（延迟、利用率、跨云容量这三件事有可验证的工程含量），但它站在一个**两头都比自己强壮**的位置上——上游是拥有数据中心的云厂商，下游是随时可以自建的高技术客户，中间的价差正在被公开的 GPU 价格战压缩。它的「换掉要付什么」列不出数据资产、合规资质或流程绑定这类硬东西，只有一次性的迁移工程量，这就是它拿不到「强」的原因。

## 3. 北极星指标

- **North Star**：**每日推理调用量（或等价的 GPU 消耗分钟数）**。官方在 Series F 公告里把「inference volume grew 40x」和收入并列，且放在前面 `[官方]` —— 这就是它自己盯的数。有媒体引用其 2026/06 达到每天 10 亿次推理调用、87 个集群、18 家云 `[媒体，未在官方公告中出现，谨慎采信]`。

- **为什么是它**：用量制生意的收入是用量的滞后函数。客户流量今天涨，账单下个月才涨；客户开始把主力模型迁进来，账单要几个季度才见顶。更重要的是，用量能提前暴露风险——**用量涨而收入不涨，就是在打价格战**，这正是 40x 对 20x 所说的事。

- **配套指标**（推断，官方未披露）：
  - **GPU 利用率**：这是毛利率的分子分母，是这门生意的生死线；
  - **净收入留存（NDR）**：用量制公司的 NDR 通常极高（客户自己长大就带动账单），但同样意味着**客户如果不长了，收入立刻掉**，没有合同托底；
  - **前 10 大客户收入占比**：从公开客户名单看集中度存疑，未公开。

## 4. AI 在业务中的作用

| 层次 | Baseten 的情况 |
|---|---|
| **AI = 产品本身** | **是，但要说清楚是哪种「是」。** 没有 AI 浪潮就没有这门生意——它卖的就是跑 AI 的地方。但它自己不做模型：产品是调度、优化和运维软件，AI 是它服务的对象，不是它的能力来源。 |
| **AI = 效率杠杆** | 明显。约 300 人做 $600M 年化，人均 $200 万，是传统 SaaS 的 8–15 倍。不过这个杠杆主要来自**用量制商业模式**（收入随客户流量自动增长，不需要按比例增加销售人头），而不是内部用 AI 干活。 |
| **AI = 营销标签** | 有一点。「AI 推理云」听起来像模型公司，实际是**跨云 GPU 转售 + 运维软件**。把「AI」两个字拿掉，它是一家云托管公司——一门好生意，但估值逻辑完全不同。 |

**自研模型还是调 API：** 都不是。它**既不训模型也不转售闭源 API**，而是托管客户带来的模型和开源权重模型。这个位置很特别——它对任何单一模型供应商**没有依赖**，反而是模型的分发渠道（Baseten for Model Labs 就是明着做这件事）。

**基础模型每次升级，是利好还是威胁：**

- **闭源模型变强、变便宜 → 威胁。** 客户直接调 OpenAI/Anthropic 的 API 就够了，不需要自己托管任何东西，Baseten 这层被跳过。
- **开源权重模型变强 → 大利好，而且是它这一年 20 倍的直接原因。** DeepSeek、Kimi、GLM、GPT-OSS 每强一次，「自己托管开源模型比调闭源 API 便宜且可控」这个论点就硬一分，而托管正是 Baseten 卖的东西。

所以它的命运绑在一件事上：**开源权重模型与闭源模型的差距会不会持续保持在「够用」的范围内**。这个变量不在它手里。

## 5. 增长引擎

1. **客户增长即自身增长（主引擎）。** 这是全篇最重要的一条：Baseten 几乎不需要「增长」，只需要**选对客户然后等**。它的客户名单是 2025–2026 增长最快的一批 AI 应用公司，它们的流量曲线自动变成 Baseten 的收入曲线。这既是它 20 倍增长最省力的解释，也是它最大的脆弱性——**它的收入质量不高于它客户的收入质量**。

2. **开发者自下而上（PLG）。** Basic 档 $0/月纯按量、开源 Truss 框架、大量模型性能优化的技术博客（transcription、embeddings、compound AI 的 benchmark 文章）。工程师先自己推一个端点上去，跑通了再让公司签 Enterprise。

3. **开源模型的「首发托管」。** 每次有重要的开源权重模型发布，谁最快提供优化好的托管端点，谁就吃掉这一波流量。Baseten for Model Labs 把这条渠道产品化了——模型实验室拿它做分发和变现，Baseten 拿到独家优化和首发位置。这条是它少数带一点结构性优势的获客路径。

4. **企业侧的自托管/混合部署。** 用 self-hosted 和 VPC 部署去接那些「数据不能出网、但也不想自建推理」的大客户（HubSpot、Notion 这类）。这条路径客单价高、迁移成本相对高，是它把「中等不可替代性」往上抬的方向。

## 6. 风险与争议

1. **毛利率是这门生意最大的黑箱，而且大概率不好看。** 它不拥有数据中心，转售跨云租来的 GPU。同赛道 Fireworks 约 50% 毛利 `[媒体]`，AI 公司普遍 50–60% `[媒体]`。有投资人直白地批评这类公司的估值方法：「看起来 VC 就是在乘收入倍数，假装毛利率不重要」`[媒体，Newcomer]`。22 倍收入 = 40 倍以上毛利，这个数字要靠增速持续兑现才站得住。

2. **收入是客户流量的镜像，没有合同托底。** 纯用量制没有承诺消费额的保护（至少未公开）。前 10 大客户的收入占比未公开，但从名单看，Cursor、Lovable 这类超高增长客户的贡献大概率不小。**这些客户有两个动作会直接砸掉收入曲线**：(a) 规模到了之后自建推理（这是所有大客户的必然路径，Cursor 已在自研推理方向投入）；(b) 融资环境转冷、烧钱放缓。一个「20 倍增长」的用量曲线，掉下来也可以同样快。

3. **上下游夹击，中间层被压薄。** 上游是拥有数据中心和芯片配额的云厂商（不需要租 GPU，成本结构天生更好），下游是技术能力极强的 AI 公司（自建门槛不高）。同层还有 Fireworks（$800M）、Together、Modal（$300M）、Replicate 在打，产品同质化程度高，价格是主要武器。「用量 40x、收入 20x」已经把价格战写在报表上了。

4. **看空视角：这可能是一次典型的周期顶部定价。** 18 个月融 4 轮、估值从 $825M 到 $13B（15.8 倍）、Series F 还要拆成 $11B/$13B 两档定价——分档定价本身就是投资人对估值有分歧的信号。这家公司的收入来自另一批同样在高倍数上融资的 AI 应用公司，而那批公司的收入又有相当部分来自 VC 的钱。**这是一条链条上的杠杆，链条上任何一环的融资环境收紧，都会沿着链条传导下来**，而 Baseten 站在最下游、按用量收费、没有合同保护。

5. **容量本身是风险敞口。** 要保证 99.99% 和低延迟，就得预留热容量；预留了没人用，钱是自己出的。这就是为什么它需要 $1.5B —— 官方说这笔钱要「aggressively invest in compute」`[官方]`。**一家轻资产公司拿 15 亿美元去买重资产，说明轻资产模式在这个规模上撑不住了。** 这是本篇最值得记的一个信号。

## 7. 给我的启发

1. **「卖铲子」这个比喻现在需要加一个限定词：你卖的铲子自己是不是也是租来的。** Baseten 确实站在最好的位置上——按用量抽取整个 AI 应用层的增长。但它的铲子（GPU）是租的，铲子的租金两年跌了 70%，客户也知道这个价。真正安全的卖铲人是拥有铲子工厂的那个。判断一家基础设施公司时，先问「它拥有什么资产」，再问「它转售什么」，最后才看增速。

2. **用量制的增速要拆成「量」和「价」两半看，这是最容易被增长故事盖住的地方。** 官方说「收入 20x、用量 40x」——绝大多数人会记住 20x，但这两个数字放在一起说的是**单价掉了一半**。同样的道理适用于任何按量计费的公司：只报收入增长而不报用量增长的，往往是在藏价格；同时报两个而且用量涨得更快的，是在诚实地告诉你「我在打价格战但我赢了量」。**看到用量增速高于收入增速，就该去算毛利。**

3. **你的收入质量不会高于你客户的收入质量。** Baseten 的客户名单漂亮得像一份 2026 年 AI 应用榜单，这既是它增长最省力的解释，也是它最集中的风险——这些客户的收入本身有相当比例来自融资，而不是稳态经营现金流。评估任何 B2B 公司时都该往上追一层：**我的客户的钱是挣来的还是融来的？** 挣来的收入抗周期，融来的收入同周期。当整条链条上的公司都在按 20–80 倍收入估值时，链条最下游那家的增速看起来最漂亮，但它承受的是全链条叠加的波动。
