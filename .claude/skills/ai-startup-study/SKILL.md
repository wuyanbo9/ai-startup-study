# AI 创业公司研究

一次输出**一家**公司的深度分析，写入归档，永不重复。

## 归档位置

归档是一个独立的 git 仓库：`ai-startup-study`

```
<仓库根>/
├── reports/
│   ├── INDEX.md                  # 已分析公司总表（先读它）
│   └── YYYY-MM-DD-<slug>.md      # 单篇报告
├── build_dashboard.py            # 看板生成器
└── index.html                    # 生成物，勿手改
```

路径一律用**仓库相对路径**（`reports/`、`build_dashboard.py`）。云端 routine 里仓库就 clone 在工作目录；本地用时先 `cd` 到这个仓库的检出目录再操作。
**不要**写到 `~/.claude/` 下面 —— 那是 Claude 的配置目录，写入会触发敏感文件权限询问，无人值守的定时任务会直接卡死。

## 执行流程

### 第 0 步：永远先读 INDEX.md

`Read` 归档目录下的 `reports/INDEX.md`。它决定了「不重复」和「能调阅」。若文件不存在，按下方模板创建。

### 第 1 步：判断意图

| 用户说 | 模式 |
|---|---|
| 无参数 /「再来一个」/「讲一家」 | **新分析** — 自动选标的 |
| 具体公司名（不在 INDEX 中） | **新分析** — 就分析这家 |
| 具体公司名（已在 INDEX 中） | **调阅** — 读出归档报告；若信息已超过 3 个月，追加一段「最新进展」并更新原文件 |
| 「列表」「我看过哪些」「INDEX」 | **调阅** — 输出总表，按赛道分组 |
| 「对比 A 和 B」 | **调阅+综合** — 读两篇归档（缺的先补做），横向对比 |

### 第 2 步：选标的（仅新分析模式）

**硬性排除**：INDEX.md 里已有的公司；OpenAI / Anthropic / Google DeepMind / xAI 等基础模型巨头本体（它们不是「创业公司学习样本」，除非用户点名）。

**排序规则 —— 增长速度优先于规模，这是最高优先级：**

1. **第一梯队（优先选）**：ARR 或核心用量在 12 个月内增长 ≥ 3 倍，或 0 → $10M+ ARR 用时 < 18 个月。哪怕绝对体量只有几千万美金，也排在体量 10 亿但同比只涨 40% 的公司前面。
2. **第二梯队**：增速快但赛道非共识 / 反直觉的（比如没人看好的垂直领域突然跑通）。这类学习价值高。
3. **规模只做次级排序**：同等增速下，选体量更大 / 融资更受关注的那家。
4. **绝不因为「有名」而选**。名气 ≠ 增速。

**赛道轮换**：查 INDEX 里最近 3 篇的赛道，本次换一个。赛道池：AI 编程、法律、医疗、客服/CX、销售、招聘、金融/会计、视频生成、语音、搜索、数据/分析、设计、教育、安全、硬件/机器人、Agent 基建、Infra/推理、消费级应用、垂直 SaaS、出海/非美国公司。

**信息新鲜度**：模型知识有截止日期，选标的**必须**先用 `WebSearch` 扫一遍近期的高增长榜单/融资新闻（关键词示例：`fastest growing AI startup ARR 2026`、`AI startup ARR growth milestone`、`Series B AI 2026 revenue multiple`），拿真实近况选，不要凭记忆选。

### 第 3 步：研究

用 `WebSearch` + `WebFetch` 交叉验证，**至少 3 个独立来源**。优先级：公司官方博客/定价页 > 一线媒体（The Information、Business Insider、TechCrunch、Sifted）> 投资机构公开文章 > 二手汇总站。

必须查到的东西：
- 收入曲线（ARR 里程碑及其**日期**，这是「增长速度」的证据）
- 最新一轮融资：金额、估值、领投方、日期
- 官方定价页（商业模式不能靠猜，去 `WebFetch` 定价页）
- 客户数 / 用户数 / 用量指标
- 团队规模（算人均创收，这是 AI 公司的关键指标）

**诚实标注可信度**，每个关键数字后缀标记：
- `[官方]` 公司自己公布
- `[媒体]` 可信媒体报道
- `[估算]` 你的推算 —— 必须写出推算依据

查不到就写「未公开」。**禁止编造数字**。

### 第 4 步：写报告

按下方模板写入 `reports/YYYY-MM-DD-<公司名slug>.md`，日期用今天。

若仓库是 git 仓库且有 remote，写完后 `git add -A && git commit && git push`，否则云端跑完沙箱销毁，归档会丢失、去重会失效。

### 第 5 步：更新 INDEX.md

追加一行到表格顶部，更新总数和赛道覆盖清单。

### 第 6 步：重新生成看板

```
python3 build_dashboard.py
```

它从 `reports/` 的全部报告重建仓库根目录的 `index.html`。每家公司在列表里是一张增长时间线（纵轴为实际数值、突变点带标注），展开后正文里是一张商业模式图，两者都来自 `model` 数据块。**不要手改 `index.html`** —— 它是生成物，改了下次就被覆盖。要改样式或抽取逻辑就改 `build_dashboard.py`。

生成器只依赖两处：frontmatter 的 `company` / `sector` / `date` 字段，以及商业模式节末尾的 ```model 数据块。报告正文的其余部分原样渲染，所以模板里的增长快照、北极星指标等章节是写给读者的，不是喂给生成器的 —— 不要为了迁就生成器而改变它们的写法。

### 第 7 步：在对话里输出完整报告

归档是给未来的，对话输出是给现在的。**把报告全文贴在最终回复里**，不要只说「已保存到 xxx」。用中文。

## 报告模板

````markdown
---
company: <公司名>
slug: <slug>
date: <YYYY-MM-DD>
sector: <赛道>
growth_tier: <第一梯队 / 第二梯队>
arr: <最新 ARR 及日期>
valuation: <最新估值及日期>
---

# <公司名> —— <一句话定位>

## 📈 增长快照（先看这个）

| 项目 | 数据 |
|---|---|
| 成立时间 | |
| 收入曲线 | 如：2024/06 $1M → 2025/03 $20M → 2026/05 $150M `[媒体]` |
| **增长倍数** | **过去 12 个月 Nx** |
| 最新估值 | |
| 团队规模 | |
| **人均创收** | ARR ÷ 人数，并与传统 SaaS（$150-250K/人）对比 |

一段话说清：**它凭什么长这么快**。这是全篇最重要的一段。

## 1. 核心产品

它到底卖什么？用户在什么场景下打开它？替代了原来的什么东西（是替代人、替代软件，还是创造新需求）？
说清「Before / After」的工作流差异。

## 2. 商业模式

- **收费对象**：谁掏钱（用户本人 / 部门预算 / 替代人力预算）
- **定价结构**：席位制 / 用量制 / 结果付费（outcome-based）/ 混合，具体价格 `[官方]`
- **单位经济**：毛利率如何？推理成本占收入比重？（AI 公司毛利常低于传统 SaaS，要点破）
- **它从谁的预算里抢钱**：软件预算还是人力预算？后者的天花板高一个数量级

**不可替代性（必答，且必须写短）**

这是全篇第二重要的判断，仅次于增长快照。但**每格不超过 40 字** —— 写不短，说明还没想清楚。

| 问题 | 怎么答 |
|---|---|
| **自己造了什么** | 真正自研、且换一家做不出来的那部分。没有就写「没有」。 |
| **转手卖什么** | 包装转售的上游能力，尽量给出它占最终价格的比例。 |
| **抽掉 AI 还剩什么** | 把 AI 叙事拿掉后，剩下的生意本体是什么。这一格最照虚实。 |
| **换掉它要付什么** | 具体的迁移成本：数据、配置、资质、流程。列不出具体东西＝没有切换成本。 |
| **上游原生做了会怎样** | 基础模型把这件事做进产品的那天，它还剩多少。 |

最后一句结论：**不可替代性：强 / 中 / 弱**，加一句话理由。

参考什么叫答得够狠 —— Retell AI 的「抽掉 AI 还剩什么」应该答成「电话线路中间件 + 合规资质」，而不是「AI 语音平台」；「转手卖什么」应该答成「LLM、TTS、线路，占最终价格约 58%」，而不是「集成了多家供应商」。

三条禁令：

1. **禁用「先发优势」「团队强」「数据飞轮」「网络效应」这类词**，除非同时给出可证伪的数字。
2. **别把「客户多」「增长快」当护城河** —— 那是结果，不是原因。
3. 如果「抽掉 AI 还剩什么」这格答案是「几乎不剩」，结论就只能是**弱**，不许在措辞上找补。

**最后必须附一个 `model` 数据块。** 看板从它生成两样东西：正文里的商业模式图，和列表卡片上的增长时间线。缺了这块，这家公司在看板上就是空的。

```model
{
  "domain":   "公司官网主域名，如 mercor.com —— 看板据此取 logo，并把正文标题里的公司名链到官网",
  "founded":  "创立时间，YYYY 或 YYYY-MM —— 看板据此排序",
  "who":      {"label": "谁有这个需求（≤14 字）", "sub": "规模 / 构成 / 集中度"},
  "need":     "他们到底卡在什么地方。写清楚频次和痛感——一天发生几次、疼在哪里。",
  "before":   {"label": "原来靠什么解决", "pain": "旧办法的代价：多少钱、多少时间、什么做不到"},
  "solution": {"label": "这家公司改成了什么", "detail": "具体做了什么，把哪个指标从多少改到多少"},
  "payer":    {"label": "谁掏钱", "buys": "他买走的到底是什么"},
  "why":      "为什么他肯付这个价。最好给出参照价——替代掉的那个东西原来值多少钱。",
  "proof":    [{"k": "指标名", "v": "值"}],
  "catch":    "这个模式没解决、或者靠转嫁解决的那个问题。",
  "unit":     "时间线纵轴的口径，如「年化收入（百万美元）」",
  "timeline": [{"d": "2025-07", "v": 50, "label": "$50M", "mark": "可选：这里增长率为什么突变"}]
}
```

写这块时守住三条：

**一、需求写在最前面，钱写在最后。** 商业模式的核心是「谁有什么需求、原来怎么被满足、你凭什么更好」，钱怎么流只是结果。不要一上来就画资金流向。

**二、`why` 必须给参照价。** 定价上限就是被替代掉的那个东西原来值多少钱：UpToDate 是 $500/席位/年、离岸坐席是 $0.30–0.80/分钟、初级律师是一份年薪。有了这个锚，读者才知道这个价是贵还是便宜；也正是这个锚决定了「抢人力预算」和「抢软件预算」的天花板差一个数量级。

**三、当获得价值的人和付钱的人不是同一批时，把这个错位讲透。** OpenEvidence 是医生免费、药企买单——这时候「用户为什么愿意付费」本身就是个错误的问题，该问的是「第三方为什么愿意为这批用户的注意力出价」。这种错位往往既是这门生意最强的护城河，也是它最脆弱的地方，`catch` 里要写明代价。

`founded` 只填年份或年月，别写「2023 年初」这种散文；只给年份时看板按年中处理。看板支持按增速、ARR、创立时间、报告时间四种排序，前两者从 `timeline` 自动算出，创立时间靠这个字段——不填这家公司在该维度就排到最后。

`domain` 只写主域名，不带 `https://` 和路径。生成器第一次构建时会去取一次 favicon，缓存到仓库的 `logos/<slug>.png`，之后以 base64 内嵌进页面 —— 所以页面依然是自包含的，也不会每次打开都请求第三方。取不到就不显示 logo，不影响构建。**新增的 logo 文件记得一起 commit**，否则下次构建又要重新联网抓。

`timeline` 至少两个点，`v` 统一用百万美元的数值（$2B 写作 2000）。**`mark` 只标真正的增长率突变点** —— 曲线折向上或者折平的那一次 —— 并写清原因（拿下锚点客户、模式跑通、外部环境变化）。一张图标一到两个就够，标满了等于没标。靠反推或估算得到的点，在 `label` 里写明。

## 3. 北极星指标

- **North Star**：这家公司内部真正盯的那一个数（不是 ARR —— ARR 是结果不是北极星）
- **为什么是它**：它如何领先于收入变化
- **配套指标**：留存、单用户用量、渗透率等 2-3 个
- 若官方未披露，写「推断」并说明依据

## 4. AI 在业务中的作用

区分清楚三层，这是判断一家公司是不是「真 AI 公司」的关键：

| 层次 | 该公司的情况 |
|---|---|
| **AI = 产品本身** | 没有 AI 这产品就不存在？ |
| **AI = 效率杠杆** | 内部用 AI 降本（小团队做大生意）？ |
| **AI = 营销标签** | 有没有名不副实的成分？ |

再答：
- 用自研模型还是调 API？模型层的依赖风险有多大？
- 基础模型每次升级，是利好它还是威胁它？

（「上游原生做了会怎样」已经在第 2 节的不可替代性表里答过，这里不要重复。）

## 5. 增长引擎

获客渠道、PLG/SLG、病毒系数、社区、渠道合作 —— 哪一条是主引擎。

## 6. 风险与争议

至少 3 条，必须包含**看空视角**。收入质量（试用期收入 vs 稳态续费）、客户集中度、模型依赖、竞争格局。

## 7. 给我的启发

3 条可迁移的判断，写给一个正在观察 AI 创业的人，不要空话。

## 来源

- [标题](URL) — 日期
````

## INDEX.md 模板

```markdown
# 已分析公司总表

按分析日期倒序。共 N 家。

| 日期 | 公司 | 赛道 | 增长梯队 | ARR（分析时） | 一句话 | 报告 |
|---|---|---|---|---|---|---|
| 2026-09-01 | Example | AI 编程 | 第一梯队 | $100M | ... | [→](2026-09-01-example.md) |

## 赛道覆盖

- AI 编程：Example
- （待覆盖：法律、医疗、语音、机器人……）
```

## 原则

- **一次一家。** 用户没要求就不要一次给两家。
- **不重复。** 写之前必查 INDEX。
- **增速 > 规模。** 选标的时反复问自己：我是不是因为它有名才选它？
- **数字必须有来源和日期。** 宁可写「未公开」。
- **别写公关稿。** 每篇都要有看空视角。
